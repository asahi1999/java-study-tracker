# Java Study Tracker 仕様書

> このファイルは、最初の仕様書に、実装前の確認（M1〜M7・Q1〜Q24）で決まった内容を反映したものです。

Java学習の3ヶ月ロードマップを管理する学習トラッカーWebアプリ「Java Study Tracker」を作ってください。
GitHubで公開するポートフォリオ作品にするので、設計・コード品質・テスト・READMEまで丁寧に作り込んでください。

## 0. 進め方（重要）

1. いきなり実装せず、まずこのプロンプトを読んで「不明点・矛盾点」「実装計画」を提示し、私の確認を取ってください
2. 確認後、「12. 実装フェーズ」の順に1フェーズずつ実装してください
3. 各フェーズの最後に lint・型チェック・テストを実行し、通ったらコミットしてください
4. フェーズの区切りで、作ったもの・確認方法を簡単に報告してください
5. このプロンプトに書いていないことで判断が必要な場合は、勝手に決めずに質問してください

**【確定】進め方の補足**

- 各フェーズが終わるたびに止まり、確認を待ってから次へ進む
- **【確定 M5】** 自動で行うのはローカルのコミットまで。push・リモート作成・デプロイは毎回確認を取る
- UI/UX は /frontend-design を使った改善サイクル（実画面のスクリーンショットで評価 → 改善点の列挙 → 修正）をフェーズ2・4・5・7・10で回す。色とフォントはフェーズ2の冒頭で案を見せて確認を取る（**【確定 Q22】**）

## 1. アプリ概要

- 目的：Java学習の進捗・学習時間を記録し、3ヶ月のロードマップを最後までやり切るためのアプリ
- 利用者：自分1人（ログイン機能なし）
- UIの言語：日本語
- 動作環境：PC・スマホのブラウザ（Chrome・Safari・Edgeの最新版）
- サーバー：使わない。データはすべてブラウザ内に保存する
- 公開先：GitHub Pages
- リポジトリ名：java-study-tracker

**【確定 Q24】データの注意**

- データはブラウザごとに保存される。PCとスマホで同期されないので、移すときはエクスポート／インポートを使う
- Safari は7日間使われなかったサイトのデータを消すことがある。対策として起動時に `navigator.storage.persist()` を呼び、README に注意書きを入れる

**【確定 Q21】公開URL**：https://asahi1999.github.io/java-study-tracker/

## 4. データ設計

### 4-1. 型定義

以下を基本にしてください。IDは crypto.randomUUID() で生成します（初期データは固定IDでOK）。

```ts
type Month = {
  id: string;
  order: number; // 1, 2, 3
  title: string; // "1ヶ月目"
  milestone: string;
};

type Step = {
  id: string;
  order: number; // 1〜8
  title: string; // "Javaの基礎"
  description: string; // 学ぶ内容
  advice: string; // 学習のアドバイス
};

type WeekStatus = 'not_started' | 'in_progress' | 'done';

type Week = {
  id: string;
  order: number;
  monthId: string;
  stepId: string;
  weekStart: number; // 何週目から（例：5）
  weekEnd: number; // 何週目まで（例：6）
  title: string; // 作るもの
  plannedHours: number; // 予定学習時間
  status: WeekStatus;
  repoUrl: string; // GitHubリポジトリURL
  startedAt: string | null; // 実際の開始日 YYYY-MM-DD
  completedAt: string | null; // 実際の完了日 YYYY-MM-DD
  memo: string; // Markdown
};

type Skill = {
  // 身につくこと（チェック項目）
  id: string;
  weekId: string;
  order: number;
  label: string;
  checked: boolean;
  checkedAt: string | null;
};

type StudyLog = {
  id: string;
  date: string; // YYYY-MM-DD
  minutes: number; // 1〜1440
  weekId: string | null;
  content: string; // やったこと
  source: 'timer' | 'manual';
  createdAt: string; // ISO日時
};

type EarnedBadge = {
  id: string; // バッジ定義のID
  earnedAt: string;
};

type BreakPeriod = {
  // 休止期間（年末年始など）
  id: string;
  label: string;
  start: string; // YYYY-MM-DD
  end: string;
};

type Settings = {
  id: 'app';
  startDate: string; // 学習開始日
  theme: 'light' | 'dark' | 'system';
  weeklyGoalHours: number; // 初期値 9
  dailyGoalMinutes: number; // 初期値 60
  breakPeriods: BreakPeriod[];
  schemaVersion: number;
};
```

- **【確定 Q9】** 「遅れ」は WeekStatus に含めず、DBにも保存しない。表示するときに予定終了日から計算する
- **【確定 Q5】** breakPeriods の初期値は空。ダッシュボードで登録を案内する

### 4-2. 保存先（IndexedDB）

- データベース名：java-study-tracker
- Dexieのスキーマ（version 1）

```ts
months: 'id, order';
steps: 'id, order';
weeks: 'id, order, monthId, stepId, status';
skills: 'id, weekId, order';
logs: 'id, date, weekId';
badges: 'id';
settings: 'id';
```

- 初回起動時（settingsが空のとき）に initialRoadmap.ts の内容と初期設定を投入する
- startDate の初期値は初回起動日
- 将来スキーマを変える場合に備えて、Dexieの version().upgrade() でマイグレーションできる構成にする
- 画面からDBを直接触らず、必ず repositories 経由で読み書きする（後で保存先を変えやすくするため）

### 4-3. localStorage に保存するもの

- 学習タイマーの状態（実行中か、開始時刻、一時停止までの累計ミリ秒、選択中の週）
  → ページを再読み込み・閉じても計測が続くようにする
- それ以外のデータはすべて IndexedDB に保存する

**【確定 P2-2】例外：テーマの写し**

- テーマ（ライト／ダーク／システム）だけは、localStorage にも写しを保存する（キー：`java-study-tracker:theme`）
- 理由：IndexedDB は読み込みが非同期で、起動直後の最初の描画に間に合わない。同期で読める localStorage から起動時に読むことで、画面がちがうテーマで一瞬光るのを防ぐ
- 正本は IndexedDB の settings。写しは、設定を読み込んだとき・変更されたときに更新する
- 起動時は index.html のスクリプトが写しを読む。写しがなければ OS の設定に合わせる

## 6. 機能詳細

### 6-1. ダッシュボード

- 全体の進捗率（プログレスリング）と「残り◯日」
- 月ごと・ステップごとの進捗率（プログレスバー）
- 今週の予定（予定日から計算した現在の週と、その未完了チェック項目）
- 今日の学習時間 / 1日の目標、今週の学習時間 / 週の目標
- 現在の連続学習日数と最長記録
- 遅れている週があれば警告カード
- 最近の学習ログ3件、最近獲得したバッジ

**【確定】**

- **Q4** 「残り◯日」は最終週の予定終了日までの日数。過ぎたら「◯日超過」と表示する
- **Q2** 現在の週が2件あるとき（11週目）は両方表示する。0件のとき（開始前・休止中・終了後）は次の未完成の週を案内する
- **Q3** 「今週の学習時間」は月曜始まりの暦週で集計する
- **Q5** 休止期間が未登録のときは、登録を案内する

### 6-2. ロードマップ一覧

- 表示切り替え：「月ごと」「ステップごと」
- 各週をカードで表示：週番号・作るもの・状態バッジ・進捗率・予定期間・GitHubリンク
- 状態バッジの色：未着手（グレー）/ 進行中（青）/ 完成（緑）/ 遅れ（赤）
- 各月のマイルストーンを表示し、その月の週がすべて完成したら「達成」表示
- 各ステップの説明とアドバイスを折りたたみで表示

### 6-3. 週の詳細

- 身につくことのチェックリスト（チェックで checkedAt を記録）
- 「完成にする」ボタン：チェック項目がすべて完了したときだけ押せる。押すと status=done、completedAt=今日
- 完成の取り消しもできる
- GitHubリポジトリURL（https://github.com/ で始まるか検証し、リンクとして開ける）
- 実際の開始日・完了日（手動で変更も可）
- メモ：Markdownで入力し、「編集 / プレビュー」を切り替え。入力は1秒ごとに自動保存
- この週の学習ログ一覧と合計時間、予定時間との比較

**【確定】**

- **Q6** 完成中はチェックリストをロックする。取り消すと「進行中」に戻り、completedAt は空になる
- **Q7** チェック項目が0件の週でも「完成にする」は押せる。進捗率は 7章のとおり 0%
- **Q16** メモは入力が止まって1秒後に保存する。画面を離れるときも保存する

### 6-4. 学習タイマー

- 開始・一時停止・再開・終了・破棄
- どの週の学習かを選択（初期値は今週）
- 終了時にダイアログで「やったこと」を入力して保存（1分未満は保存しない）
- 日付をまたいだ場合は開始日の日付で記録する
- 実行中はブラウザのタブタイトルに経過時間を表示

**【確定】**

- **Q2** 現在の週が2件あるとき、初期値は表示順が先の未完成の週にする
- **Q15** 24時間を超えた場合は1440分に丸めて保存し、ダイアログで注意を出す。秒は切り捨てる

### 6-5. 学習ログ

- 一覧（新しい順）：日付・週・時間・内容・タイマー/手動の区別
- 絞り込み：期間・週・ステップ
- 手動追加・編集・削除（削除は確認ダイアログ）
- 絞り込み結果の合計時間を表示

### 6-6. 統計

- 学習カレンダー（GitHub風ヒートマップ）：学習期間全体を表示。色の濃さは5段階（0分 / 1〜29分 / 30〜59分 / 60〜119分 / 120分以上）。マスにカーソルを合わせると日付と時間を表示
- 週別の学習時間の棒グラフ（週の目標を基準線で表示）
- ステップ別の学習時間の割合
- 予定ペースと実績の比較（折れ線）：予定の累計進捗率と実際の累計進捗率を週ごとに表示
- 累計学習時間・平均学習時間（1日あたり / 学習した日あたり）

**【確定】**

- **Q19** ヒートマップの範囲は、開始日〜最終週の予定終了日。範囲外のログがあればその日まで広げる
- **Q3** 週別の棒グラフは月曜始まりの暦週で集計する
- **Q17** 予定ペースは、2週分の週のチェック項目を週数で按分する。実績は checkedAt で集計する
- **Q18** 平均（1日あたり）の分母は、開始日〜今日の日数。休止日は除く

### 6-7. 実績バッジ

- 獲得済みはカラー、未獲得はグレーで条件を表示
- 学習ログやチェックが更新されたときに判定し、新しく獲得したら画面にトースト通知
- 一度獲得したバッジは条件を満たさなくなっても消さない
- バッジ定義：

| ID         | 名前                 | 条件                    |
| ---------- | -------------------- | ----------------------- |
| first-log  | はじめの一歩         | 初めて学習ログを記録    |
| first-done | 初完成               | 初めて週を完成          |
| streak-3   | 三日坊主卒業         | 3日連続で学習           |
| streak-7   | 1週間継続            | 7日連続で学習           |
| streak-30  | 習慣化マスター       | 30日連続で学習          |
| hours-10   | 10時間突破           | 累計10時間              |
| hours-50   | 50時間突破           | 累計50時間              |
| hours-100  | 100時間突破          | 累計100時間             |
| month-1    | 1ヶ月目クリア        | 1ヶ月目の週をすべて完成 |
| month-2    | 2ヶ月目クリア        | 2ヶ月目の週をすべて完成 |
| oop        | オブジェクト指向入門 | ステップ④を完成         |
| sql        | DBデビュー           | ステップ⑤を完成         |
| spring     | Spring Bootデビュー  | ステップ⑥を完成         |
| repo-5     | GitHub常連           | GitHub URLを5つ以上登録 |
| on-time    | 予定どおり           | 遅れなしで1ヶ月分を完成 |
| complete   | ロードマップ完走     | すべての週を完成        |

**【確定】**

- **Q10** on-time は、いずれかの月で全週が完成し、各週の完了日が予定終了日以内のときに獲得する
- **Q11** repo-5 は、URLが入っている週が5つ以上のときに獲得する。同じURLも週ごとに数える
- **Q12** month-1・month-2・oop・sql・spring は初期データの固定IDで判定する。編集で該当の月・ステップを消すと獲得できない。streak 系は最長記録で判定する

### 6-8. ロードマップ編集

- 月・ステップ・週・チェック項目の追加・編集・削除
- 週とチェック項目は上下ボタンで並び替え
- 削除時、関連する学習ログは削除せず weekId を null にする（確認ダイアログで説明）
- 「初期ロードマップに戻す」：進捗・ログを残すか消すかを選べる確認ダイアログ付き

**【確定】**

- **M7** 週が残っている月・ステップは削除できない。先に週を移動するか削除する（Week の monthId・stepId が必須のため）

## 7. 計算ルール（lib に純粋関数として実装）

- 進捗率 = チェック済み項目数 ÷ 全項目数（全体・月・ステップ・週ごと）。項目0件なら0%
- 予定期間：週Nの予定開始日 = 開始日 + (N−1)×7日、予定終了日 = 開始日 + weekEnd×7日 − 1日。休止期間に重なった日数分、それ以降の予定を後ろにずらす
- 現在の週：今日が含まれる予定期間の週
- 遅れ判定：今日が予定終了日を過ぎていて status が done でない
- 状態の自動更新：チェックが1つ以上 または ログが1件以上ある未着手の週は「進行中」にする
- 連続学習日数：1日の合計学習時間が1分以上の日が何日続いているか。今日まだ学習していない場合は昨日までで数える（今日の時点で途切れ扱いにしない）
- 日付はすべてローカル時刻（日本時間）の YYYY-MM-DD で扱う

**【確定】**

- **Q1** 休止日は「数えない日」として扱う。休止期間をまたぐ週は終了日が延び、それ以降の週は同じ日数だけ後ろへずれる。6日間の休止なら、以降の週の開始曜日も6日分ずれる
- **Q2** 現在の週は2件になることがある（11週目）。開始前・休止中・終了後は0件になる
- **Q8** 自動で「進行中」にするとき、startedAt が空ならその日を入れる。チェックやログをすべて消しても「未着手」には自動で戻さない
- **Q23** 進捗率は項目数で計算するので、週によって重みが違う（1週目は6項目で15%、8週目は2項目で5%）
- **P3-1** 進捗率は四捨五入して整数のパーセントにする。ただし「100%」は全部終わったときだけ、「0%」は1つも終わっていないときだけ表示する（39/40 は 98%、199/200 は 99%、1/400 は 1%）
- **P3-2** Q8 の「その日」は「最初の記録の日付」とする。チェックした日と学習ログの日付のうち、いちばん早い日を開始日にする（過去の日付でログを足した場合は、そのログの日付）。今日より先にはしない
- **P3-3** 開始日が空のまま「完成にする」を押した場合は、今日を開始日にも入れる
- **P3-4** 休止期間が週の途中にある場合、休止中の日もその週を「現在の週」とする（予定期間に含まれるため）。0件になるのは、休止期間が週と週の間にあるときだけ。休止中かどうかは別に判定する
