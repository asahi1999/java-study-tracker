## 骨格

- **土台は C（ダンジョン工房）の「1本の作品が育つ」**。批評役（ユーザー目線）の点数1位。「動くもの」「すぐ結果」に一番効く
- **入口は B**: 起動したら「次の1ステップ」がもう表示されている。「1ステップだけ」で終われる
- **つまずきは A**: エラー図鑑（発見 → 捕獲）。修理問題を各章に入れる。休んだあとは「おかえりの宝箱」と易しい1問
- **出力の見せ方は A の方式**: 標準出力の文字をそのままタイルで描く（独自 API なし、手元のターミナルでも同じ文字が出る、判定は文字列比較）。色やアニメーションの拡張は後回し
- **世界観はダンジョン1本**（ユーザーは「任せる」。批評役がダンジョンを推した）。ただし世界観は見た目の皮で、データと判定には持ち込まない。「テストが通ると灯りがともる」は「松明がともる」にする
- **最小単位は「ステップ」（1〜3分）**。C の部品をステップに分け、ステップごとに自動保存
- **収集は2つだけ**: 技カード（文法）とエラー図鑑。作品はダンジョン1つ。ポイントのショップはなし
- **レベルはある**。ただし時間ではなく「できたこと」（クリアしたステップ）に付ける
- **連続記録・遅れの警告・罪悪感を生む表示はなし**。「今週は Java を休む」と自分で選べるボタンを置き、完走見込みから外す

## Java の実行

- ブラウザ: teavm-javac（Apache-2.0）をリポジトリに固定して同梱（`public/java/teavm-javac/<版>/`、SHA256SUMS・SOURCE.md・THIRD_PARTY_NOTICES.md）
- 手元: VS Code＋JDK 25。作業フォルダの zip、`Check.java`、クリアコードを貼る方式
- 問題ごとの「ブラウザで動かない場合の代わりの教材」は作らない。代わりの手段は「手元で実行して結果を貼る」1つ
- ブラウザと JDK の違い（HashMap の順番、Random、例外メッセージ、ファイル入出力など）は、禁止リストと CI の出力一致検査で防ぐ
- エラー図鑑は例外の型と javac のエラー（英語・日本語の両方の文言）で判定する

## 教材

- 形式: 1問1フォルダ、本物の `.java` ファイル（critic-tech.md 7-4）
- 本線の量: 小問 約110問＋手元課題 約8本＋Spring Boot 1本（週3時間で2月末に終わる）
- CI で正しさを自動検証（critic-tech.md 3-2）。文章は作成者とは別のエージェントがレビューし、`reviewed: true` のものだけ公開
- 書き出しは `void main()`（コンパクトソース）、クラスの章で `public static void main` に移り「現場ではこの形」と明示
- **進め方**: まず MVP（第0〜2章）を完成させ、そのあと第3章以降を足していく。今回の作業の中で、できるところまで全章を作る
