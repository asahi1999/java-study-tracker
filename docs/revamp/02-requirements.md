## 1. 目的

- Java を「やろうと思える」状態を作る。記録するアプリではなく、開いたらそのまま Java を書いて動かすアプリにする
- 2027年2月末までに、Java の基礎〜Spring Boot 入門を終える。週3時間でも間に合う量にする。3月は予備
- 作り終わるのを待たずに学び始める。第0章だけ遊べる状態を最初に作り、そこから使い始める（7-1、03-design.md 13章）
- 書いたコードが「ダンジョン」の絵になり、章ごとに1本の作品（ダンジョン）が育つ
- 就職用ポートフォリオとして、README・テスト・コード品質・教材の自動検証を見せられる状態にする

### 目的にしないこと

- 学習時間を管理すること（記録は自動で裏に残すだけ）
- 他人に使ってもらうこと（利用者は本人1人）
- AI 機能（アプリから外部 API は呼ばない。質問文を作ってコピーするだけ）

## 3. 4つの壁と対策

| 壁                                    | 対策（機能 ID）                                                                                                                                                                                                        |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 1回が重く感じて始められない        | 最小単位は1ステップ（1〜3分）（F-HOME-1）。開いたら次のステップがもう表示されている（F-HOME-1）。「1ステップだけ」で終われる（F-HOME-2）。書きかけは自動保存（F-STEP-9）。手元課題は15〜25分の段階に分ける（F-PROJ-2） |
| 2. 何から手をつければいいか分からない | 道は1本。ホームには次の1つだけを出す（F-HOME-1）。持ち時間を選べば合うものを1つ出す（F-HOME-3）。地図で全体と今いる場所を見せる（F-MAP-1）                                                                             |
| 3. スマホや遊びに流れる               | 開く前: 初回の準備で PWA のインストールと Dock 登録を案内（F-SETUP-1）。開いた後: 実行から結果まで約1秒（N-PERF）。休んでも罰がなく、戻ると宝箱（F-BACK-1）。連続記録・遅れの警告は出さない                            |
| 4. Java が面白くない                  | 標準出力の文字がそのままダンジョンのタイルになる（F-TILE-1）。章ごとに作品（ダンジョン）が育つ（F-WORK-1）。テストが通ると松明がともる（F-STEP-7）。エラーは図鑑で「発見→捕獲」（F-DEX-1）                             |

### 罪悪感を生まないための決まり（全画面共通）

- 出さないもの: 連続学習日数、遅れの警告、予定との比較、赤い警告色の進捗、サボった日数
- 減る数字を出さない（レベル・松明・図鑑は減らない）
- 「今週は Java を休む」を自分で選べる。選んだ週は完走見込みの計算から外す（F-REST-1）

## 4. 体験の流れ

### 4-1. 初回起動

1. URL（または PWA）を Chrome で開く
2. 裏で v1 のデータを移す（F-DATA-1）。旧記録があれば（判定は 03-design.md 3-3）、トーストで1回だけ「v1 の学習記録 ◯時間を『旧記録』に引き継ぎました」。読めなかったときは、ホームの上に閉じられる帯「v1 の記録を読み込めませんでした ［v1 のデータを JSON で書き出す］」を出す（F-DATA-4）
3. ホームに最初のステップ（第0章の説明カード「ダンジョンの入口」）が、問題文の冒頭つきで表示されている。設定や目標の入力は求めない
4. 「▶ つづける」→ 説明カード（1分）→ 最初の小問。`System.out.println("#####");` の行を1つ足して実行すると、右側に石の壁のタイルが並ぶ
5. 画面の表示が終わったら、裏で Java の実行環境（約7.6MB）をダウンロードし始める。ホームの隅に進み具合を小さく出す
6. 3ステップ終えたら、ホームに1回だけ「毎回すぐ開けるように: Chrome でインストールして Dock に置く（1分）」のカードを出す（F-SETUP-1）。閉じたら二度と出さない。Chrome 以外では出さない
7. 第0章の最後のステップが「手元の準備」（p00、約10分）。ホームの「次の1ステップ」にそのまま出る。作業フォルダの zip を落として VS Code で開き、`java Check.java` を1回動かす

- 非対応のブラウザ（Safari 18.1.1 など）で開いたとき: ステップ画面の上に「Chrome で開く」の案内（URL のコピーつき）を出す。書く問題は「手元で実行して結果を貼る」で進められる（F-RUN-6）

### 4-2. 通常の1回（平日の夜、15分）

1. Dock の PWA を開く。ホームに「次のステップ: 第2章 松明を並べる（約3分）」と問題文の冒頭が出ている
2. 「▶ つづける」。エディタには書きかけのコード（または ひな形）が入っている
3. `Cmd+Enter` で実行。約1秒で、出力がタイルで描かれ、テストの数だけ松明が順にともる
4. 全部ともるとクリア。解説（2〜3行）、レベルの増分、手に入れた技カードを出す
5. 「次のステップへ（約3分）」「ここで終える」が同じ大きさで並ぶ。どちらでもよい。やめても何も言わない
6. 閉じるだけ。時間は自動で記録される（画面が見えていて、操作がある間だけ）

### 4-3. 7日以上空いた後

1. ホームの「次の1ステップ」の上に「おかえり。宝箱があります ［開ける］」の帯が出る（次のステップは隠さない）
2. 開けると、宝箱のモーダル（05-visual-design.md 7-8）。中身は「1分で終わる易しい解き直し1問」と「おみやげ1つ」（タイルの見た目の替え。F-BACK-1）
3. 「1問だけやる」で、前にクリアした易しい問題の解き直し（1〜2分。F-BACK-2）。「宝箱はあとで開ける」で閉じても、宝箱は次に開くまで残る
4. そのあと、ふだんの「次のステップ」に戻る
5. 「◯日空いた」「遅れ」はどこにも出さない。完走見込みの日付が静かに動くだけ（ホームの「ペース」）

### 4-4. 手元課題（休日、1時間）

1. ホームで「持ち時間: 30分以上」を押す（押さなくてもよい）。「手元課題 p02 部屋ジェネレーター 段階1（約20分）」を提案
2. 「VS Code で始める」→ 作業フォルダの場所（`~/java-quest/ch02`）と手順が出る。作業フォルダが古ければ「新しい作業フォルダ（第2章だけ）」の zip を出す
3. VS Code で `Room.java` を書き、`Cmd+Shift+B`（タスク登録済み）で `java Check.java` が動く
4. ターミナルにタイル風の部屋と `[1/3] 床を描く ... PASS` が並び、最後に `クリアコード: JQ1-p02-1/3-K7QF`
5. アプリに戻ってクリアコード（または出力まるごと）を貼る。開いている課題と違うもの（別の課題のクリアコードや出力）は記録しない。かかった時間を確認して（初期値は「始める」からの経過時間）記録
6. 段階1で用事ができたら、そこでやめてよい。次は段階2から

### 4-5. 行き詰まったとき

1. 同じステップで2回失敗、またはエラーが出ると、ヒントの横の「質問文を作る」が光る（いつでも押せる）
2. ヒントは3段（方向 → 具体例 → ほぼ答え）。使っても罰はない
3. 「質問文を作る」→「どこが怪しいと思う？」を1行書ける（空でもよい）→「ヒントだけ／説明して／答えも」を選ぶ
4. 「コピーして Claude を開く」。問題文・自分のコード・結果・学習段階が入った文章がクリップボードに入り、`https://claude.ai/new` が新しいタブで開く。アプリからは何も送らない
5. 教材がおかしいと思ったら「問題を報告」。GitHub の Issue 作成画面が、題名と本文（問題 ID・自分のコード）入りで開く。送るのは自分
6. ブラウザで動かない・結果が怪しいときは「手元で実行」。1ファイルをコピーして `java JqCheck.java`、出力を貼れば判定される。コードはアプリで書き、手元は判定するだけ（手元で直したら、エディタに貼り戻す）。別の問題の出力を貼ったときは記録しない

| F-STEP-3  | 穴埋め・修理・実装: エディタで書いて実行し、テストで判定する                                                                                                                                                                                        | M    |

| F-STEP-8  | ヒント3段。押した段だけ開く。罰なし。使った最高の段を記録                                                                                                                                                                                           | M    |
| F-STEP-9  | 書きかけの自動保存（入力が止まって1秒後と、画面を離れるとき）。次に開くと続きから                                                                                                                                                                   | M    |

## 6. 非機能要件

### 6-1. オフライン（N-OFF）

- N-OFF-1: 2回目以降は、ネットなしで全画面・全教材・Java の実行が動く（PWA）
- N-OFF-2: Java 実行環境は、初回のダウンロードが終わった時点でオフラインに備える。設定画面で「保存済み」が分かる
- N-OFF-3: 作業フォルダの zip だけはネットが必要でもよい（手元課題を始めるときだけ使うため）

### 6-2. 対応ブラウザと非対応時の表示（N-BR）

| 区分                   | ブラウザ                                     | 根拠                                                                                                                     |
| ---------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 対象（PC）             | Chrome（最新）。PWA も Chrome でインストール | Chrome 158 で teavm-javac が動いた（実測。04-spikes.md 1章）。CI の E2E も Chromium で確かめる                           |
| 対象外（動けば使える） | Safari・Firefox・Edge など                   | 確かめない。WasmGC が使えれば動くこともある。利用者の Safari 18.1.1 は WasmGC 非対応で動かない見込み（04-spikes.md 1章） |
| 最低限（スマホ）       | iOS Safari・Android Chrome                   | 画面が崩れない・読める。書く問題は PC を勧める                                                                           |

- N-BR-1: 起動時に WasmGC を判定し、最初の Java 準備で「Hello」を実際にコンパイル・実行して確かめる。結果を保存する
- N-BR-2: 非対応のときの表示（ステップ画面の上、閉じられる）: 「このブラウザでは Java を動かせません。Chrome で開くか、『手元で実行』を使ってください」＋［URL をコピー］。版の数字は画面の文言に書かない（設定の説明にだけ、確かめた版を書く）
- N-BR-3: 非対応でも、説明カード・予想・クイズ・手元課題・図鑑・記録・設定は使える。書く問題は「手元で実行して結果を貼る」で、最後まで進められる
- N-BR-4: Safari で「Dock に追加」した Web アプリは、保存領域が Safari と別の可能性がある（未確認）。Chrome を対象にするので、インストールの案内は Chrome だけに出し、Safari の確認はしない

### 6-4. アクセシビリティ（N-A11Y）

- N-A11Y-1: キーボードだけで全操作できる。エディタからは `Esc` → `Tab` で出られる（画面に表示）
- N-A11Y-2: 文字と背景のコントラストは WCAG 2.2 AA（通常 4.5:1）
- N-A11Y-3: 色だけで意味を伝えない。松明は「済／未」を形と文字（aria-label）でも出す。タイルには「文字」表示がある
- N-A11Y-4: 実行結果と判定結果は `aria-live="polite"` で読み上げる
- N-A11Y-5: `prefers-reduced-motion` のときは松明・宝箱のアニメーションを止める
- N-A11Y-6: UI は日本語。本文とボタンは v1 の BIZ UDPゴシック、見出しは DotGothic16（16／24／32px だけ）、コードは IBM Plex Mono（05-visual-design.md 4-3。フォントは自前で配る）

### 6-5. データの保存と移行（N-DATA）

- N-DATA-1: 保存先は IndexedDB の新しい DB `java-study-tracker-v2`。v1 の DB `java-study-tracker` は読むだけ（v1 に戻せるように）
- N-DATA-2: 起動時に `navigator.storage.persist()` を依頼（v1 と同じ）
- N-DATA-3: v1 からの移行は、成功するまで起動のたびに試す（成功・v1 なしで止める）。書くときは1トランザクション。失敗しても v1 の DB は無傷。設定画面に状態を出す
- N-DATA-4: エクスポートは全データ（v1 の旧記録を含む）。インポートは Zod で検査し、上書き前に件数を見せて確認。v2 形式のファイルに旧記録が無ければ、今の旧記録は残す（開発サーバーで学んだ記録を本番に移すとき、本番で移した v1 の旧記録を消さないため）
- N-DATA-7: 開発サーバー（revamp ブランチの `npm run dev`）は決まったポートで動かす。ポートが変わると保存先（オリジン）が変わり、記録が見えなくなるため。公開のときは、開発サーバーでエクスポート → 本番でインポートして記録を移す
- N-DATA-5: 教材の更新で問題 ID は変えない。クリアの記録は教材の版が変わっても残る
- N-DATA-6: 名前の衝突を避ける: 同じオリジン（`asahi1999.github.io`）のほかのサイトと分けるため、DB・キャッシュ・localStorage のキーに `java-study-tracker` を付ける

### 6-6. セキュリティ（N-SEC）

- N-SEC-1: 学習者のコードは Web Worker の中で、WebAssembly として実行する。画面（DOM）には触れない
- N-SEC-2: 実行用の Worker は毎回新しく作り、時間切れ・出力の上限・異常で `terminate()` する
- N-SEC-3: 学習者の Java から JavaScript を呼ぶ口（JSO など）は渡さない。外部への通信はできない
- N-SEC-4: 教材と旧記録の Markdown は HTML を通さずに描く（react-markdown、生の HTML は無効）
- N-SEC-5: CSP を `<meta>` で付ける（`'wasm-unsafe-eval'` を許可、`unsafe-eval` なし、`worker-src 'self'`）。`<meta>` の CSP で teavm-javac が動くことは確かめた（04-spikes.md 5章）。`<meta>` の CSP は Worker の中には効かない（GitHub Pages はヘッダーを付けられない）。Worker は学習者のコードを動かす場所なので、JS を呼ぶ口を渡さないこと（N-SEC-3）で守る
- N-SEC-6: 外部へ出るのは、利用者が押したときの新しいタブ（claude.ai、GitHub の Issue 作成画面）だけ。中身は URL の引数とクリップボード
- N-SEC-7: インポートするファイルは 20MB まで。形が違えば何も書かない

### 6-7. 品質（N-QUAL。ポートフォリオ）

- N-QUAL-1: lint・整形・型チェック・単体テスト・ビルド・教材検証・E2E（Playwright）が CI で通る状態でだけコミットする
- N-QUAL-2: 判定・タイル・クリアコード・移行・見込みなどの計算は純粋関数にし、単体テストを付ける
- N-QUAL-3: README に目的・工夫（ブラウザ内 Java、教材の自動検証）・構成図・動かし方を書く
- N-QUAL-4: 同梱する teavm-javac のハッシュを CI で毎回照合する。`THIRD_PARTY_NOTICES.md` を `public/java/teavm-javac/<版>/` に置き、README からリンクする。LICENSE は追加しない（01-decisions.md）

## 8. 章ごとの「使ってよい文法・API」

- 教材の検証（content-verify）の根拠。ひな形（Starter）と模範解答（Solution）、予想のコード（Program）、説明カードの例を検査する。判定用のコード（Tests・ハーネス）は対象外
- **積み上げ式**: 第 N 章では第0〜N章のものを使える
- 自分で宣言した名前（変数・メソッド・クラス）と、同じ問題で配るファイルの名前は、いつでも使える
- 表記: `Type.method` は static、`Type#method` はインスタンスのメソッド、`new Type` は生成
- 問題の前書きの `allowExtra` で、理由つきで例外を足せる（例: 第2章の絵で `String#repeat` を先取り）

### 8-3. ブラウザで動かす問題で使わない書き方（全章共通）

- 理由: teavm-javac と JDK で結果が違う、または動かない（research・critic-tech の実測）
- 検査: content-verify が正規表現で検出して CI を落とす。さらに模範解答を両方で動かして出力を比べる
- 学習者のコードにも同じ正規表現を当て、当たったら結果の下に注意を出す（F-RUN-7。判定は変えない）。正規表現は教材の検査と画面で1つのものを使う
- `double` の表示（`Double.toString`）が JDK と同じかは未確認。CI で約100の値を比べ、違えば「`double` は `printf("%.2f")` で出す」をこの表に足す（03-design.md 6-9）

| 使わない                                                                                     | 理由                                                                                                | 代わり                                                   |
| -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `HashMap`・`HashSet`・`Map.of`・`Set.of`・`Map.ofEntries`                                    | 表示の順番が違う（実測）                                                                            | `TreeMap`・`LinkedHashMap`・`TreeSet`、並べ替え          |
| `Random`・`Math.random`・`ThreadLocalRandom`                                                 | 値の列が違う                                                                                        | 決まった配列・文字列                                     |
| `getMessage`・`printStackTrace`・例外を直接 `println`                                        | メッセージが null になる（実測）                                                                    | `getClass().getSimpleName()`                             |
| `String.format`・`printf` の `%e`                                                            | 例外になる                                                                                          | `%.2f`                                                   |
| `Files`・`FileReader`・`FileWriter`・`Path`                                                  | 動かない（実測）                                                                                    | 手元課題（第7章）                                        |
| `System.in`（`new Scanner(System.in)` 以外）                                                 | 例外になる                                                                                          | `Scanner`                                                |
| `System.currentTimeMillis`・`nanoTime`・`LocalDate.now` などの現在時刻                       | 毎回違う                                                                                            | 決まった日付                                             |
| `System.getProperty`・`getenv`・`Runtime`・`Class.forName`・リフレクション                   | 環境で違う・動かない                                                                                | —                                                        |
| `hashCode()` の結果や `Object` の既定の `toString`（`Hero@1b6d3586`）を表示                  | 値が違う                                                                                            | `toString` を上書き                                      |
| `Thread`・`Thread.sleep`・`System.exit`                                                      | 終わり方が違う（調査）                                                                              | 後続のコマ送り（F-TILE-3）                               |
| `IO.println` など `IO` クラス                                                                | 書き方をそろえるため（動作はする。実測）                                                            | `System.out.println`                                     |
| 拡張 `for` の中で、そのリストを `remove`                                                     | teavm-javac だけ `ConcurrentModificationException`（実測）                                          | `removeIf`、新しいリストを作る                           |
| 結果を使わないキャスト `(Integer) o`                                                         | teavm-javac で `ClassCastException` が出ない（実測。Chrome・WebKit・Node で同じ。04-spikes.md 1章） | 結果を必ず使う                                           |
| `static` な `Scanner`、`static` なフィールドに頼る書き方（第4章以降、ケースが2つ以上の問題） | 判定のケースは同じ実行の中で順に動くので、前のケースの値が残る                                      | `main` の中で作る。教材は、そういう問題をケース1つにする |
| Java 22 以降で入った API                                                                     | teavm-javac の標準ライブラリは Java 21 相当                                                         | —                                                        |
