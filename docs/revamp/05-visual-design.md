## 1. 評価

### 1-1. 確かめたこと

- 各案の PNG（幅 1366px）を見た
- ヘッドレス Chrome で4画面×3案を幅 1280px・1440px（高さ 900px）で撮り直した（file://、サーバーなし）
- ライトテーマはどの案にもない（3案ともダークのみ）。ライトは 4章でこの文書が決める
- 主な観察
  - 案1: 1280px でも、ホームの「次の1ステップ」カードが最初の画面に全部収まる。ステップ画面は3列で、実行・テスト・出力・クリアが高さ 900px に収まる。ただし 1280px ではエディタの幅が約 520px しかなく、折りたたみの帯がはみ出す
  - 案2: ステップ画面で、テスト・出力・クリアの表示が 900px の下に落ちる（スクロールしないと結果が見えない）。エラー時のページの高さは約 1400px
  - 案3: 3画面とも 900px に収まる。左のアイコンだけのレールは、文字のラベルがない

点の理由（短く）

- 案1
  - 壁 5: 「行注釈（出力の文字とタイルを同じ行の高さで並べる）」が、01-decisions の「出力の文字をそのままタイルで描く」と一致。Java の `println` が絵になる手応えが一番強い。「書くのは return の1行だけ」「このステップだけで終えてOK」で1回の重さを下げている
  - 次の1ステップ 5: 左上の唯一の松明色の枠。問題名・約2分・完成図・始めるが1枚に収まる
  - ゲーム性 4: 8×8 ドットのタイル、松明＝テスト、図鑑のルーン色。UI 自体は控えめ
  - 読みやすさ 4: 本文は普通のゴシック。見出しのドット文字が 22〜30px で、ドットの格子に合わずにじむ
  - 実装 4: `clip-path` の角欠けは Tailwind の自作ユーティリティで再現できる。タイルは SVG の矩形だけ。フォーカスの輪が `clip-path` で切れる点は直す必要あり
  - アクセシビリティ 4: 文字のコントラストは全部 AA 以上（実測 5.0〜13.8:1）。赤はコンパイルエラーの位置だけ。11px の注記がある
- 案2
  - 雰囲気と手触りは一番。明朝の見出しと石の質感で、作品として見せたときの完成度も高い
  - ただし、ステップ画面で結果が画面の下に落ちる。「実行 → すぐ結果」が崩れる
  - ページ全体の明るさ `--lit`、松明からの距離でタイルの明るさを計算、背景のノイズ（feTurbulence）、明朝と丸ゴシックの2書体の日本語フォント。実装とテストの手間が大きく、PWA の容量も増える
  - 背景の質感の上に長文を置くので、長時間は疲れやすい
- 案3
  - IDE の作りで読みやすさと見栄えは一番。ホームで「前回の続きのコード」を見せる案は、再開の重さを下げる良い工夫
  - ただし、見た目が「道具」に寄る。v1（記録用の道具）で勉強する気にならなかった経緯（00-brief）を考えると、「Java がつまらない」「遊びに流れる」への効きが弱い
  - 左レールがアイコンだけ（文字なし）。03-design の「上部の横並びナビ」とも違う。⌘K 検索は要件にない機能

### 1-3. 選んだ理由

- 合計は案1と案3がほぼ同点。決め手は、このアプリの目的が「勉強する気になること」である点
  - 見栄えと読みやすさは、実装で直せる（フォント、サイズ、列の幅）
  - 「出力が絵になる」手応えと、ゲームとしての手触りは、あとから足しにくい。案1はそれを画面の中心に置いている
- 案1の見た目の約束（文字＝地図、1文字＝1マス）は、03-design 8章のタイル描画の仕組みとそのまま一致する。見た目と仕組みが同じ話をしている
- 案2は一番美しいが、結果が画面外に落ちる点と実装の重さで外した

## 4. デザイントークン

### 4-1. テーマの扱い

- 基準はダーク。ライトは「羊皮紙」の配色を用意する（F-SET-1 のライト・ダーク・システム）
- 切り替えは v1 と同じ `darkMode: 'class'`（`<html class="dark">`）。`src/hooks/useTheme.ts` をそのまま使う
- **テーマに関係なく暗いままの面（`well`）**: エディタ、出力の文字、タイル、宝箱の部屋
  - 03-design 8-1「タイルの面は常に暗い背景」に、エディタと出力の文字もそろえる
  - 理由: エディタ・出力・タイルは「地下の窓」として1つの面に見せる。構文の色を1組だけ検証すればよい
- 色の値は v1 と同じく `R G B` の3つの数で CSS 変数に入れ、Tailwind から `rgb(var(--x) / <alpha-value>)` で使う（`bg-panel`、`text-ink-dim`、`bg-torch/15` など）

### 4-3. フォント

| 役割                       | フォント      | 太さ            | 使う所                                                                                                                    |
| -------------------------- | ------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 見出し・数字（ゲームの層） | DotGothic16   | 400             | 画面の見出し、レベル、図鑑の番号、小ラベル。**16 / 24 / 32px だけ**（ドットの格子に合う大きさ）。本文・ボタンには使わない |
| 本文・ボタン               | BIZ UDPGothic | 400 / 700       | 説明、問題文、ボタン（N-A11Y-6。v1 から継続）                                                                             |
| コード・出力               | IBM Plex Mono | 400 / 500 / 600 | エディタ、出力の文字、javac の原文、日付、`<kbd>`                                                                         |

- 読み込み: Google Fonts の CDN は使わない（PWA のオフラインと CSP のため）。`@fontsource` を npm で入れて自前で配る
  - `@fontsource/biz-udpgothic`（v1 で導入済み）、`@fontsource/ibm-plex-mono`、`@fontsource/dotgothic16`（**パッケージ名は自信がない。導入時に `npm view` で確認**）
  - `font-display: swap`
  - 日本語フォントは unicode-range で分かれたファイルが多い。workbox の precache（`globPatterns` に woff2 あり）に全部入れると重くなるので、フォントは precache から外し、実行時キャッシュ（CacheFirst）にする
- 予備: `"Hiragino Sans", "Yu Gothic UI", sans-serif`／等幅は `"SF Mono", Menlo, monospace`
- 案1のモックの IBM Plex Sans JP は使わない（要件 N-A11Y-6 に合わせる）。BIZ UDPGothic に 500 はないので、モックの 500 は 400 か 700 に読み替える
- 等幅は `font-variant-ligatures: none`
- 数字は `font-variant-numeric: tabular-nums`（v1 と同じ）

### 4-5. 余白・角・線・影

- 余白: 4px の格子。使うのは Tailwind の `1 2 3 4 6 8 12`（4 / 8 / 12 / 16 / 24 / 32 / 48px）だけ
- 角丸は使わない。代わりに**ピクセルの角欠け**
  - `notch-2`: 角を 2px 欠く（パネル、チップ、ヒント）
  - `notch-4`: 2段に欠く（ボタン、宝箱の部屋）
- 線: 2px（ドット1つ分）。区切りは `line`、押せる部品の枠は `line-strong`
- 影: ぼかしの影は使わない
  - `shadow-press`: 主ボタンの下に 4px のベタ（`torch-press`）。押せる板に見せる
  - 光（松明のにじみ）は放射グラデーションの飾り。`clip-path` の要素の外には出せないので、親の要素に付ける

### 4-6. 動き

| 名前            | 時間・緩急                 | 使う所                 |
| --------------- | -------------------------- | ---------------------- |
| `duration-fast` | 120ms                      | ホバー、押した時       |
| `duration-base` | 200ms                      | 開閉、目盛りが増える   |
| `duration-slow` | 400ms                      | 松明がともる           |
| `ease-ui`       | `cubic-bezier(.2,.8,.2,1)` | UI の動き              |
| `ease-pixel`    | `steps(3, end)`            | ドットの物（炎、宝箱） |

- `ignite`: 松明がともる。不透明度 0→1 と大きさ 0.6→1 を `steps(3)` で 240ms。テストが通った順に 120ms ずつずらす
- `sweep`: エラー図鑑に発見したとき、カードを光が1回横切る（900ms、1回だけ）
- `breathe`: 宝箱の光の呼吸（3.2秒、くり返し）。宝箱のモーダルの中だけ
- ステップ画面では、くり返す動きを置かない（長く読む画面なので）。松明の炎のゆらぎもなし
- `prefers-reduced-motion: reduce` のとき
  - 全部のアニメーションとトランジションを止める（下のコード）。状態は最後の形で即座に出す
  - 読み上げ（`aria-live="polite"`）の文は動きの有無に関係なく同じ（N-A11Y-4、N-A11Y-5）

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
