# 企画 A（ゲームデザインの視点）: 灯台守 — Lighthouse Keeper

作成: 2026-11-27 ／ 担当: ゲームデザイン視点

---

## 1. コンセプト名と一言キャッチ

- **名前**: 灯台守（とうだいもり）— Lighthouse Keeper
- **キャッチ**: 「書いたコードが、夜の港に灯りをともす。」

### 核になるアイデア（3つだけ）

1. **標準出力がそのまま絵になる**
   - `System.out.println` で出した文字を、アプリがタイル（海・壁・灯り・船）に変換して描く
   - for 文で三角形を出せば、それが灯台になる。2次元配列を出せば、それが港の地図になる
   - 「すぐ結果が出る」「動くものが作れる」を、第1問目から体験させる
2. **テストケース＝灯り**
   - 1問ごとにテストが3〜6個あり、実行すると通ったテストから順に灯りがともる
   - 全部ともると、その問題で書いたコードが港町の建物として残る
   - ポイントもコインもない。報酬は「自分のコードが動いた証拠」だけ
3. **エラーは敵ではなく、図鑑の生き物**
   - 初めて出たエラー（`cannot find symbol`、`NullPointerException` など）は「発見」として図鑑に載る
   - 直してテストが通ると「捕獲」になる
   - 「直す」という一番つらい作業を、集める楽しみに変える

### v1 との違い

|              | v1（記録するだけ）         | 灯台守                                     |
| ------------ | -------------------------- | ------------------------------------------ |
| アプリの役割 | 勉強の外側で記録する       | 勉強そのものをアプリの中でやる             |
| 報酬         | 時間や日数に対するバッジ   | 自分のコードが描いた絵と建物               |
| 予定         | 12週の予定と「遅れ」の警告 | 予定なし。「到着予測」だけ。遅れの表示なし |
| 記録         | 手で入力                   | 自動（遊んだ時間が航海日誌になる）         |

## 2. 体験の流れ

### 2-1. 初回起動（3分）

- 画面は暗い夜の港。灯台は消えている
- 一行だけ表示される
  - 「灯台守さん、ようこそ。まず、灯りを1つともしてください。」
- 説明画面やチュートリアルはない。いきなり第1問のエディタが開いている

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("ここに港の名前を書く");
    }
}
```

- 文字列を自分の好きな港の名前に変えて `Ctrl+Enter`
- 港の入口に看板が立ち、そこに書いた名前が出る。灯台の最初の灯りがともる
- ここまで1分。「Java で何かが動いた」が最初の体験になる
- 続けて「手元の JDK でも動かしてみる」クエストが出る（任意・5分）
  - 同じコードを VS Code で `java Main.java` するだけ
  - 実行結果に出る「合言葉」（後述）を貼ると、灯台の窓に明かりが入る
- v1 のデータがあれば、ここで自動で引き継ぐ
  - 学習ログ → 「旧航路の記録」として航海日誌の先頭に入る
  - バッジ → 港の資料館に「旧港のスタンプ」として飾る

### 2-2. 1回の学習セッション（平日の夜、25分あるとき）

- アプリを開く。画面の中央にボタンが1つだけある
  - **「次の灯りをともす（約5分）」**
  - その下に小さく「航海の長さ: 1灯（5分）／ 1航海（25分）／ 遠洋（60分〜）」
- 「1航海」を選ぶと、次の順で進む
  1. **準備運動（1分）**: 前に解いた問題の「出力予言」を1問。ほぼ必ず正解できる。最初の灯りがすぐともる
  2. **海図カード（2分）**: 新しい文法の説明カード。最大3枚。カードの中のコードもその場で動かせる
  3. **本番（15〜20分）**: 3〜4問。種類は「予言」「穴埋め」「修理」「実装」「絵を描く」が混ざる
  4. **寄港（1分）**: 今日ともした灯り、新しく見つけたエラー、次の問題の予告（タイトルと完成図の影だけ）
- 実行ボタンを押すと
  - 0.5秒以内にテストの灯りが1つずつともる（小さな音つき。音は設定で消せる）
  - 通らなかったテストは赤くならず、「霧」がかかる。クリックすると「期待した出力／実際の出力」の差分が出る
- 3回続けて失敗するか、同じ問題に8分いると、灯台の横に**「狼煙（のろし）」ボタン**が光る（後述。チャットで質問する機能）
- 25分経っても止めない。寄港画面で「ここで帰港する？」と1回だけ聞く
- 帰港すると、次回の最初の問題が「途中まで書いた状態」で保存される。次は続きの1行から始められる

### 2-3. 週末、時間がたっぷりあるとき（遠洋 = ボス戦）

- 章の最後に「ボス」がある。VS Code と手元の JDK 25 で作る、30〜60分の課題
- ボスは3つの「区画」に分かれていて、区画ごとに途中のテストがある
  - 15分しかなくても区画1だけ進められる
- 流れ
  1. アプリでボスの配布ファイル（zip）をダウンロード
  2. VS Code で `Boss.java` を書き、`java Check.java` を実行
  3. テストが通ると、ターミナルに「合言葉」が出る（例: `KEEPER-3A9F-C2`）
  4. 合言葉をアプリに貼ると、ボス撃破の演出。港町に大きな建物（例: 灯台そのもの、造船所）が建つ
- ボスで作ったものは、そのまま GitHub に置ける形になっている（ポートフォリオ用）

### 2-4. 2週間サボった後

- 開くと「おかえりなさい、灯台守さん。航海に出ていたようですね」
- 港に**おみやげの船**が1隻着いている
  - 中身は寄り道クエスト（遊び用の問題）1つと、灯りの色の追加（見た目だけ）
  - 「サボった日数」「途切れた連続日数」はどこにも出さない
- 最初の問題は必ず**復帰クエスト**（前回やった内容の予言1問、1分）
- 到着予測の日付が少し後ろにずれるだけ。赤い表示や警告はない
  - 予測が2月末を超えたら「寄り道を飛ばす航路」を提案する（本線だけなら間に合う、と具体的に示す）

### 2-5. 1ヶ月後（2026年12月末ごろ）

- 週3時間ペースなら、第3章（メソッド・配列）まで終わっている（約12時間）
- 港町にあるもの
  - 自分の for 文が描いた灯台、2次元配列が描いた港の地図、マインスイーパーの盤面
  - エラー図鑑は10〜15種。それぞれ「どの問題で出会い、どう直したか」が自分のコードつきで残っている
- 年末年始で0時間の週があっても、町は1つも壊れていない

### 2-6. 完走（2027年2月下旬）

- 最終章のボス: Spring Boot で「港の窓口」（REST API）を作る
- 自分の API が返した船の一覧が、港の画面に船として浮かぶ（接続方法は 7章を参照）
- 灯台の全灯演出。最後に「航海記」ページができる
  - 章ごとに作ったもの（絵・建物）と、そのコード、エラー図鑑、合計時間
  - 就活や内定先との会話で見せられる1ページ
- 3月は予備。寄り道クエストや、苦手だった章の「再航海」（別問題）が残っている

## 3. 4つの壁への効き方

### 壁1: 1回が重い

- 最小単位を「1灯＝5分」にした。ボタン1つで始まり、5分で1つ終わる
- 起動したらすぐエディタ。メニューを選ぶ・教材を開く・環境を立ち上げる、がない
- 最初の1問は必ず簡単な準備運動。開始1分以内に「成功」を1回入れる
- 前回は途中で止めて保存する。「白紙から始める」が起きない
- ボスも3区画に分けて、重い課題を15分単位に切った

### 壁2: 何から手をつけるか分からない

- 道は1本。画面の中央に「次の灯り」が常に1つだけある
- 寄り道は本線を終えた章にしか出ない。選択肢が増えて迷うことがない
- 章の最初に「この章で作るもの」の完成図（影）を見せる。何のために学ぶかが先に分かる

### 壁3: スマホや遊びに流れる

- 正直、スマホを止める仕組みは作れない（通知もなし）。代わりに「PC で開いたときの引きの強さ」で勝負する
  - 次の問題の予告は「完成図の影」で見せる。続きが気になる状態で終える（連続ドラマの引き）
  - 1問5分なので「1問だけ」が成立する。ゲームの「あと1ターン」と同じ構造にする
  - 開いてから最初の手応えまで30秒以内（PWA としてデスクトップにインストールし、1クリックで再開）
- スマホでは港町と図鑑を眺めるだけにする。スマホで勉強した気にさせず、「続きは PC で」と一言だけ出す

### 壁4: Java が面白くない

- Java の文法を「何かを描く・動かす道具」として出す
  - `for` → 灯台を描く。2次元配列 → 地図を描く。クラス → 船を作る。継承 → 船の種類で動きを変える
- 解いた後もコードを触れる「いじり場」がある。数字を変えると灯台が高くなる、などおもちゃとして遊べる
- エラー図鑑で、つまずきにも「集める」楽しさがつく
- 最終章で、自分が作った Spring Boot のサーバーが港を動かす。「Java で動くものを作った」で終わる

### 時間のばらつきと罪悪感への対策（まとめ）

- 連続日数（ストリーク）はやめる。v1 の連続学習日数・遅れ警告は引き継がない
- 何もしない週があっても、町も灯りも減らない（衰退・罰のしくみはゼロ）
- 時間が空くほど「おみやげの船」が少し豪華になる（休むことを損にしない）
- 予定ではなく「到着予測」だけ出す。週5時間のペースでも週1時間のペースでも、同じ画面で日付が動くだけ

## 4. 主要機能一覧

### 必須（MVP に入れる）

| 機能                         | 内容                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------- |
| クエスト画面                 | 問題文・エディタ（シンタックスハイライト）・実行・テストの灯り表示。`Ctrl+Enter` で実行   |
| ブラウザ内実行               | 短い問題を実行する（技術は別担当が選定）                                                  |
| 手元実行モード               | ブラウザで動かせない問題・環境向け。コピー → `java` で実行 → 合言葉や出力を貼る           |
| 出力タイル描画               | 標準出力の文字をタイルに変換して描く（`*`=灯り、`~`=海、`#`=壁、`S`=船 など）             |
| 港町マップ                   | クリアした問題が建物になる。建物をクリックすると自分のコードが見られる                    |
| エラー図鑑                   | javac・実行時エラーの文言を辞書（正規表現）で判定し、日本語の説明と「よくある原因」を出す |
| 狼煙（質問文ジェネレーター） | 問題文・自分のコード・エラー・試したことをまとめ、チャットに貼る質問文を作ってコピー      |
| ヒントのはしご               | 問題ごとに3段のヒント（方向 → 具体例 → ほぼ答え）。使ってもペナルティなし                 |
| 航海の長さ選択               | 1灯（5分）／1航海（25分）／遠洋（ボス）                                                   |
| 途中保存                     | 書きかけのコードを自動保存。次回はそこから再開                                            |
| おみやげの船・復帰クエスト   | 3日以上空いたときの迎え方                                                                 |
| 到着予測                     | 残りの本線の量 ÷ 最近4週の平均ペース。遅れ表示はしない                                    |
| 航海日誌                     | アプリ内で遊んだ時間を自動記録。ボスなど VS Code の作業は「遠洋タイマー」で計る           |
| v1 データ引き継ぎ            | IndexedDB の学習ログ・バッジを自動で取り込む。JSON インポートも可                         |
| PWA                          | インストールとオフライン                                                                  |

### あれば良い

| 機能             | 内容                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| いじり場         | クリア後のコードを自由に書き換えて遊べる（記録には影響しない）                     |
| 寄り道クエスト   | 本線とは別の遊び問題（例: ASCII で花火、簡単な暗号、迷路の自動解き）               |
| ★チャレンジ      | 追加のテスト（境界値など）を通すと建物に装飾がつく                                 |
| 再航海           | 苦手だった章を別の問題でもう一度。3月の予備期間用                                  |
| 港の窓口接続     | 最終章で、localhost の Spring Boot API から船を読み込んで港に浮かべる              |
| 航海記ページ     | 完走時に作る1ページのまとめ。印刷・PDF 保存しやすい形                              |
| 音               | 灯りがともる音、ボス撃破の音（初期はオフでも良い）                                 |
| スマホの予言問題 | スマホで1分の予言問題だけ解ける。壁3に逆効果になる可能性もあるので、使ってから判断 |

### あえて入れないもの

- ポイント・コイン・ショップ（v1 のバッジと同じ「貼っただけ」になるため）
- 連続日数、遅れの警告、ランキング
- 1日の目標時間（ばらつきが大きいので、達成できない日が罪悪感になる）

- 期間: 2026-11-27 〜 2027-02-28 は約13.3週。週3時間で約40時間

- 1章 = 小問 12〜18問 ＋ ボス1体。小問は全体で約130問

## 6. 学習コンテンツの形式

### 6-1. 問題の種類

| 種類     | 所要時間          | 内容                                                   | 判定方法                                             |
| -------- | ----------------- | ------------------------------------------------------ | ---------------------------------------------------- |
| 予言     | 1〜2分            | コードを読み、出力を予想して入力 → 実行して答え合わせ  | 予想した文字列と実際の出力の比較                     |
| 穴埋め   | 2〜3分            | 1〜3か所の空欄を埋める                                 | 実行してテスト（実行できない場合は答えの候補と比較） |
| 修理     | 3〜5分            | バグ入りのコード。テストが落ちている。直して全灯させる | テスト                                               |
| 実装     | 5〜10分           | メソッドを1つ書く                                      | テスト                                               |
| 絵を描く | 5〜10分           | 出力で指定の形を描く。完成図の影と重なると全灯         | 出力の比較（タイルで差分を表示）                     |
| ボス     | 30〜60分（3区画） | VS Code で書く中くらいの課題                           | 配布した `Check.java` が出す合言葉                   |

- 1章の中の並び: 予言 → 穴埋め → 修理 → 実装 → 絵を描く、の順に少しずつ自分で書く量を増やす
- 「修理」を各章に必ず入れる。エラー図鑑の生き物はここで多く出会う

### 6-2. 例1: 予言（第1章、1分）

```java
public class Main {
    public static void main(String[] args) {
        int a = 7;
        int b = 2;
        System.out.println(a / b);
        System.out.println(a % b);
        System.out.println((double) a / b);
        System.out.println("合計: " + a + b);
    }
}
```

- 4行それぞれの出力を予想して入力する
- 正解（JDK 25 で確認済み）
  ```
  3
  1
  3.5
  合計: 72
  ```
- 4行目で「9」と答えた人が多いはず。外れた行は灯りがともらず、「文字列 + 数値の順番」の海図カードが開く
- 外れても損はない。「予言が外れた」こと自体が学びになる、と演出で伝える（外れた行に「なるほど」スタンプ）

### 6-3. 例2: 絵を描く（第2章、7分）

- お題: 「高さ `height` の灯台を描け」。右側に完成図の影がタイルで出ている

```java
public class Main {
    public static void main(String[] args) {
        int height = 4;
        for (int row = 0; row < height; row++) {
            // 1. 左に空白を (height - row - 1) 個
            // 2. 灯り * を (row * 2 + 1) 個
            // ここを書く
        }
        for (int i = 0; i < 3; i++) {
            System.out.println(" ".repeat(height - 2) + "|#|");
        }
    }
}
```

- 解答例

```java
        for (int row = 0; row < height; row++) {
            String spaces = " ".repeat(height - row - 1);
            String light = "*".repeat(row * 2 + 1);
            System.out.println(spaces + light);
        }
```

- 出力（JDK 25 で確認済み）。アプリはこれを `*` = 光るタイル、`|#|` = 灯台の柱 として描く

```
   *
  ***
 *****
*******
  |#|
  |#|
  |#|
```

- テスト（灯り）は `height = 2, 4, 7` の3つ。どれも完成図と一致すれば全灯
- クリア後は「いじり場」で `height` を 12 にすると、大きな灯台になって港の奥に立つ

### 6-4. 例3: 修理（第6章、4分）

- お題: 「積み荷の数を数えるメソッドが、港で爆発している。直せ」

```java
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class Cargo {
    static Map<String, Integer> countCargo(List<String> items) {
        Map<String, Integer> counts = new HashMap<>();
        for (String item : items) {
            counts.put(item, counts.get(item) + 1);
        }
        return counts;
    }
}
```

- 実行すると出るエラー（JDK 25 で確認済み）

```
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because the return value of "java.util.Map.get(Object)" is null
```

- エラー図鑑に「NullPointerException（ぬるぽ）」が**発見**として載る
  - 図鑑の説明: 「中身がない（null）ものを使おうとした。今回は、まだ入っていないキーを `get` したので null が返った」
- 直し方の例（どちらでも全灯）

```java
counts.put(item, counts.getOrDefault(item, 0) + 1);
// または
counts.merge(item, 1, Integer::sum);
```

- 直すと図鑑の NullPointerException が**捕獲**に変わり、「第6章・積み荷の修理で捕獲。直したコード」が記録される
- ★チャレンジ（任意）: 空のリスト、全部同じ品目、のテストも通す

## 7. 実装の難しさと最小構成（MVP）

### 7-1. 難しいところ

| 項目                   | 難しさ             | メモ                                                                                                                                                                                                                    |
| ---------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ブラウザ内実行         | 高                 | 別担当の調査次第。下の「動かせない場合」で必ず代わりが成り立つようにする                                                                                                                                                |
| 問題の量と正しさ       | 高                 | 約130問＋ボス9体。解答例とテストを CI（GitHub Actions の JDK、無料）で全部実行し、正しさを自動で確かめる。ポートフォリオとしても見せられる                                                                              |
| 出力タイル描画         | 低                 | 文字 → タイルの対応表と CSS グリッドで足りる                                                                                                                                                                            |
| エラー図鑑             | 中                 | javac・実行時のよくあるエラー30種ほどを正規表現で判定する辞書。英語の文言を日本語の説明に対応づける                                                                                                                     |
| 合言葉                 | 低                 | 同じハッシュ関数を Java（Check.java）と TypeScript に書くだけ                                                                                                                                                           |
| 港町マップ             | 中                 | 建物の配置は固定（章ごとに区画が決まっている）。自由配置にはしない                                                                                                                                                      |
| 港の窓口接続（最終章） | 中〜高・自信がない | https の GitHub Pages から `http://localhost:8080` を読むのは、ブラウザの制限（混在コンテンツ・ローカルネットワークへのアクセス制限・CORS）にかかる可能性がある。ブラウザごとの挙動に自信がないので、実装前に確認が必要 |

### 7-2. ブラウザで Java を動かせる前提／動かせない場合

| 問題の種類 | 動かせる場合       | 動かせない場合の代替                                                                      |
| ---------- | ------------------ | ----------------------------------------------------------------------------------------- |
| 予言       | 実行して答え合わせ | 正解の出力を問題データに持っておき、文字列で比較（体験はほぼ同じ）                        |
| 穴埋め     | 実行してテスト     | 候補の答え（複数可）との比較。または手元実行                                              |
| 修理・実装 | 実行してテスト     | 「コピー」ボタン → VS Code の `quests/` フォルダに貼って `java Q0612.java` → 合言葉を貼る |
| 絵を描く   | 出力をそのまま描く | 手元で実行した出力をアプリに貼ると、同じように描いて判定する                              |
| ボス       | （もともと手元）   | 変わらない                                                                                |

- 代替の場合、1問あたり20〜30秒の手間が増える。「すぐ結果」は弱まるが、タイル描画・灯り・図鑑・合言葉はすべてそのまま成り立つ
- 手元実行の手間を減らすため、第0章で `quests/` フォルダ（全問題の雛形と Check クラス入り）を一度だけダウンロードしてもらう
- 最終章の港の窓口に接続できない場合の代替
  - ボスの配布物に、港の表示用の HTML を `src/main/resources/static/` に入れておく。Spring Boot 自身が港の画面を出すので、ブラウザの制限を受けない
  - または API の JSON をコピーしてアプリに貼る

### 7-3. 最小構成（MVP）

- **目的**: 最初の1ヶ月（第0〜3章、約12時間分）を遊べる状態にして、本当に勉強したくなるかを確かめる
- 範囲
  - クエスト画面（予言・穴埋め・修理・実装・絵を描く）
  - ブラウザ内実行 または 手元実行モード（どちらか動く方。両方あるのが理想）
  - 出力タイル描画、テストの灯り表示
  - 港町マップ（第0〜3章の区画だけ）
  - エラー図鑑（第0〜3章で出るエラー15種ほど）
  - 狼煙、ヒントのはしご
  - 航海の長さ選択、途中保存、おみやげの船、復帰クエスト
  - 航海日誌（自動記録）、到着予測
  - v1 データ引き継ぎ、PWA
  - 問題データ: 第0〜3章の小問約50問＋ボス3体。CI で解答例を全実行
- MVP の後
  - 第4章以降の問題を、学習の進みより1章先回りで追加していく
  - いじり場、★チャレンジ、寄り道、航海記ページ、港の窓口接続

## 8. この案の弱点

- **物語が子どもっぽく感じる可能性**
  - 「灯台守さん」の語りが合わないと、むしろ冷める。語りは1画面1行までに抑え、設定で物語をオフにできるようにする
- **問題を作る量が多い**
  - 約130問＋ボス9体は、アプリを作るより重い作業になりうる
  - 作り手（Claude Code と本人）と学習者が同じ人なので、問題を確認するとネタバレになる。解答は本人が見ない前提で、CI の自動テストで正しさを担保するしかない
- **後半の章は「絵」にしにくい**
  - 例外・Stream・Spring Boot はタイルで描きにくく、前半ほどの「描ける楽しさ」は出ない。集計結果を棒グラフのタイルにする、などで補うが弱い
- **テストを通すことが目的になりやすい**
  - オブジェクト指向の「設計の良し悪し」は自動テストで測れない。第4〜5章は「動くけど設計がまずい」状態でも全灯してしまう
- **スマホに流れることは止められない**
  - この案は「PC で開いた後の引き」を強くするだけ。PC を開くまでの壁には直接効かない
- **新しさは1ヶ月で薄れる**
  - 灯りや図鑑の演出は最初が一番楽しい。2ヶ月目以降は「作るものが毎章変わる」ことだけが頼り
- **ブラウザ実行がない場合、体験の中心が弱る**
  - 代替でも成り立つが、コピー → 実行 → 貼り付けの往復で「すぐ結果」の気持ちよさは確実に落ちる
- **復習（学習科学の観点）が薄い**
  - 復習は準備運動と復帰クエストだけ。忘れにくくする仕組みは、学習科学の案の方が強いはず。組み合わせる余地がある
- **最終章のローカル API 接続は技術的に未確認**
  - ブラウザのセキュリティ制限にかかる可能性があり、自信がない。代替（Spring Boot 側で港の画面を出す）を本命にしておく方が安全
