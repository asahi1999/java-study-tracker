# 企画 B：ひとくち Java（学習科学・習慣化の視点）

> 担当の視点：始めるハードルを極限まで下げる／想起練習・間隔反復・即時フィードバック・適切な難易度／自己効力感
> 前提資料：`docs/revamp/00-brief.md`（ヒアリング結果）、`README.md`（v1）、`docs/SPEC.md`

---

## 1. コンセプト名と一言キャッチ

**ひとくち Java（Java Bites）**

> **「開いた瞬間に1問目。1問30秒、1セット5分。気づいたら、動くゲームが1本できている。」**

- v1 は「記録する」アプリだった。記録は勉強が終わった**後**の行動なので、始める理由にならなかった
- B 案は「勉強そのもの」をアプリの中に入れる。**アプリを開く＝もう1問目を解いている**状態にする
- 設計の柱は3つ
  1. **入口を極小に**：最小単位は「1問（30秒）」。やめてもいい。続けたければ続く
  2. **思い出させて、覚えさせる**：読ませるより解かせる（想起練習）。間を空けて出し直す（間隔反復）。答えたら1秒で正誤が返る
  3. **「できた」の証拠を積む**：解けた問題・動いたプログラム・身についた技が、減らない形で貯まっていく（自己効力感）
- ゲーム性は「技カード（覚えた知識が育つ収集要素）」と「工作物（自分で作った動くゲーム）」の2本立て。**報酬は"時間"ではなく"身についたこと"に払う**

## 2. 体験の流れ

### 2-1. 初回起動（最初の3分）

1. URL を開く。設定画面もチュートリアルもない。いきなりこう出る

   ```
   ▶ 数当てゲーム（あなたが3週間後に作るもの）
   > 50
   もっと小さい
   > 30
   もっと大きい
   > 42
   3回目で正解！

   ──────────────
   Q1. 42 を 7 に変えると、2行目には何が出る？
   [ もっと小さい ] [ もっと大きい ] [ 正解！ ]
   ```

   - ブラウザで Java が動く場合：本物を実行して見せ、数字を自分で書き換えて「実行」まで押してもらう
   - 動かない場合：あらかじめ記録した出力を、ターミナル風に1行ずつ再生する（見た目は同じ）

2. 答えると即座に正誤。正解なら「技カード：if 文 を手に入れた（銅）」が出る
3. 続けて4問（全部、正解率が高くなるように作った易しい問題）。**最初の1セットは"必ずできる"**ことを優先する
4. セット終了画面
   - 「5問中5問。技カード3枚。所要 4分12秒」
   - 「次はいつやる？」を**1タップで**選ぶ（いつ・どこで を決める。後述の「実行意図」）
     - 例：`[PC を開いたら最初に]` `[夕飯のあと]` `[授業の課題が終わったら]` `[自分で書く]`
   - 「PC の Dock に置く（PWA としてインストール）」の案内
5. v1 のデータがあれば、裏で自動で取り込む。v1 の累計学習時間は「これまでの貯金」として初期 XP に変換して見せる（「ゼロからじゃない」と感じてもらう。後述の「エンダウド・プログレス効果」）

### 2-2. 1回の学習セッション（5分〜2時間、長さは事前に決めない）

- **起動 → 即1問目**。トップ画面の真ん中に「今日の1問目」がもう出ている。ボタンを押す前に問題文が読める
- 画面上部に、前回決めた「きっかけ」が小さく出る：`PC を開いたら最初に、ひとくち Java`
- **1セット＝5問・約5分**
  - 内訳：思い出し（復習）2問 → 新しい問題 3問
  - 1問目は必ず「復習のうち一番易しいもの」。ウォームアップで成功から入る
- セット終了ごとに3択。**どれを選んでも褒め方は同じ**

  ```
  [もう1セット（5分）]  [工作する（VS Code で 15〜60分）]  [今日はここまで]
  ```

  - 「今日はここまで」を押すと、次回の最初の問題の**チラ見せ**が出る（「次回：じゃんけんの勝ち負けを1行で判定する」）

- **「1問だけ」ボタン**：やる気ゼロの日用。1問解いたら「今日はこれで OK」と明示的に終われる
- 時間が取れる日は「工作」に入る（後述の VS Code 課題）。アプリが課題ファイルをコピーさせ、VS Code で書いて `java Xxx.java` で実行。判定用コードが「合言葉」を出したらアプリに貼ってクリア

### 2-3. 詰まったとき（チャットで質問する機能）

- 同じ問題で2回まちがえる／工作でエラーが出た、の2つのタイミングで「質問文を作る」ボタンが出る
- 押すと、**自分で1行だけ書く欄**が出る：「どこが怪しいと思う？」（空欄でも進める）
  - 自分で説明しようとすることで、送る前に自分で気づくことがある（自己説明）
- 「ヒントだけ欲しい／答えも欲しい」を選ぶ。デフォルトは**ヒントだけ**（自分で解く余地を残す）
- 下の形の質問文がクリップボードに入る。あとは Claude などを開いて貼るだけ

  ```
  Java を学び直しています（専門学校4年、文法は少し分かる程度）。
  【やっていること】第3章 配列とメソッド／じゃんけんの勝敗判定
  【問題】judge(me, enemy) で WIN / LOSE / DRAW を返す
  【自分のコード】
  （ここにコード）
  【実行結果・エラー】
  NG: judge(1, 0) -> WIN（期待: LOSE）
  【自分の予想】% の計算で負の数になっているかも
  【お願い】答えは書かずに、ヒントを1つだけください。
  ```

- チャットで分かったら、アプリに戻って「分かったことを1行で」を書ける。書いた1行は**自分専用の復習カード**になり、数日後に出題される（自分で言葉にしたものは覚えやすい＝生成効果）

### 2-4. 1ヶ月後（12月末）

- 週3時間ペースなら第4章（クラス）あたり。週ごとのばらつきは気にしていない画面になっている
- トップに出るのは「連続日数」ではなく、**減らない数字**だけ
  - 解いた問題数、技カード（銅・銀・金の枚数）、動かした工作物の数
- 「完走見込み：2月14日ごろ（予備あと2週）」。遅れても赤くならない。予備が減るだけ
- 年末に1週まったく開かなかった場合
  - 次に開いたとき「おかえり。前回は『モンスター同士のバトル』を作ったところ」
  - 復習が溜まっていても**1回に出す復習は最大10問まで**。古いものから優先して、残りは静かに後ろへずらす
  - 最初の1セットは易しめに自動調整（「思い出しセット」）
- 1ヶ月前の自分が間違えた問題がたまに出て、今は解ける。解けると「12/2 には間違えた問題。今回は 18秒で正解」と出る（過去の自分との比較で、伸びを実感）

### 2-5. 完走（2月中旬〜下旬）

- 最終章：自分のテキスト RPG のランキングを返す Spring Boot の API を立てて、ブラウザで JSON が返ってくるのを見る
- 「工作物ギャラリー」に9本並ぶ（数当て → じゃんけん → … → Web API）。全部 GitHub に置けば就活のポートフォリオにもなる
- 技カードの金の枚数＝「2ヶ月以上たっても思い出せた知識」の数。3月の予備期間は、銀や銅のカードを金に育てる復習と、研修「Java上級」に向けた寄り道クエストに使える

## 3. 4つの壁への効き方

### 壁1：1回が重く感じて始められない

| 仕掛け                                                           | なぜ効くか                                                                                                                                                   |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 最小単位は「1問・30秒」。「1問だけ」ボタンで終わってよい         | 行動のハードルを下げると、やる気が低い日でも実行できる（BJ Fogg の行動モデル：行動は「動機×能力×きっかけ」がそろったとき起きる。能力側＝簡単さを上げる発想） |
| 起動したらもう1問目が表示されている（クリック0回で問題が読める） | 「どこを開いて、何を選んで…」という摩擦をなくす。始める前の決定をゼロにする                                                                                  |
| セッションの長さを事前に決めない。5分セットを積むだけ            | 「2時間やらなきゃ」という見積もりが重さの正体。最初は5分しか約束しない                                                                                       |
| 1セット目の最初の問題は、復習のうち一番易しいもの                | 成功から入ると次に進みやすい（経験則。強い研究根拠は**自信なし**）                                                                                           |
| 終わるときに次回の最初の問題をチラ見せ                           | 「途中のものは気になる」を使う。ただし、いわゆるツァイガルニク効果は再現性に疑問があるとされ、**根拠は弱め（自信なし）**                                     |

### 壁2：何から手をつければいいか分からない

- **選ばせない**。「今日の1問目」はアプリが決める（復習の期限＋カリキュラムの次の問題）
- カリキュラムは1本道。章の中は「見る（例）→ 予測する → 並べる → 埋める → 書く → 作る」の順で、少しずつ手放していく（解き方の例から始めて、だんだん自分でやる部分を増やす＝例題のフェーディング。認知負荷理論の流れの手法）
- 迷ったら押すのは常に同じ1つのボタン：**「次の1問」**
- 長めの工作も、アプリが課題ファイル（ひな形と判定コード入り）を渡すので「何を作ればいいか」で止まらない

### 壁3：スマホや遊びに流れる

正直に言うと、**アプリでスマホを止めることはできない**（通知なし・PC 主体の制約もある）。だからできることに絞る。

- **実行意図（if-then プラン）**：「PC を開いたら、最初にひとくち Java」を初回に1タップで決め、毎回画面に出す。「いつ・どこで・何を」を事前に決めると実行率が上がることは、ゴルヴィツァーの研究とそのメタ分析で繰り返し示されている（効果の大きさの具体的な数値は**自信なし**のため書かない）
- **PC 側の入口を最短に**：PWA にして Dock に置く。ブラウザのスタートページに設定する手順、macOS のログイン項目で起動時に開く手順を設定画面に載せる（アプリの機能ではなく案内）
- **スマホより先に"1問目"が目に入る**：PC を開いた直後の数秒で問題文が読める状態を作る。迷う時間を作らない
- **流れても戻りやすい**：途中で抜けても、セットの途中から再開できる。「中断」に罰はない
- 物理的な工夫（スマホを別の部屋に置く等）は、初回の「次はいつやる？」の画面で1行だけ提案する

### 壁4：Java 自体が面白くない

- **全部の章で「動くゲーム」を作る**。文法は「ゲームを作るための道具」として出てくる
  - 例：`int` の割り算 → ダメージ計算、`if` → 数当ての判定、クラス → モンスター、`Map` → アイテム図鑑、Stream → ランキング
- 9本の工作物は**1本の RPG に育っていく**（「コンソール・クエスト」）。前の章の成果物が次の章の素材になるので、作ったものが無駄にならない
- **予測してから実行する**（PRIMM：Predict → Run → Investigate → Modify → Make の流れ。英国の学校のプログラミング教育で使われている手法）
  - 「動かす前に出力を当てる」だけで、ただ読むより退屈しない。外れたときに「なんで？」が生まれる
- 改造問題：「動くゲームのルールを1か所だけ変える」。ゼロから書くより楽しく、すぐ結果が見える
- **すぐ結果が出る**：短い問題は答えた瞬間（1秒以内）に正誤と解説。ブラウザで Java が動くなら、書いたコードの実行結果もその場で出る

| XP とレベル                        | XP は減らない。問題1問、工作1本ごとに加算                                                                                                                                                                                     |
| VS Code 工作課題                   | ひな形と判定コード入りの1ファイルをコピー。全テスト通過で「合言葉」が出る → アプリに貼ってクリア                                                                                                                              |
| 質問文ジェネレーター               | 問題文・自分のコード・エラー・自分の予想をまとめて、コピーできる質問文を作る。「ヒントだけ／答えも」切り替え                                                                                                                  |

| PWA・エクスポート／インポート      | オフラインで動く。JSON で全データを書き出し・読み込み                                                                                                                                                                         |

### あれば良い（MVP の後）

| 機能                   | 内容                                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ブラウザ内 Java 実行   | 別担当の調査結果しだい。動けば「書く」「改造」問題をブラウザ内でテスト実行。`JavaRunner` という差し替え口を用意しておき、なければ自己採点＋ VS Code にまわす |
| 工作物ギャラリーの再生 | 自分の工作物の実行結果（合言葉と一緒に貼ってもらった出力）をターミナル風に再生                                                                               |
| 寄り道クエスト         | 各章に任意の追加問題（SQL、Git、テスト、研修「Java上級」向けのジェネリクス・並行処理の入口など）                                                             |
| 過去の自分との比較     | 「◯月◯日に間違えた問題。今回は◯秒で正解」                                                                                                                    |
| 週の小目標を自分で選ぶ | 「1セット／30分／3時間」から選ぶ。初期値は「週1セット」（最低ラインを極小に）                                                                                |
| 問題のバリエーション   | 同じ問題の数字違いを複数用意し、復習で丸暗記にならないようにする                                                                                             |
| キーボードだけで解答   | 1〜4 キーで選択、Enter で次へ（PC 主体なので効果大）                                                                                                         |
| 統計                   | 正答率の推移、技カードの分布、学習時間（v1 の統計の後継）                                                                                                    |

### 入れないもの（意図的に）

- **毎日の連続記録（ストリーク）**：週0時間の週が必ずある前提なので、途切れた瞬間に「もういいや」になりやすい（ダイエット研究でいう「どうにでもなれ効果」に近い現象。学習アプリでの直接の研究は**自信なし**）。代わりに減らない数字だけを見せる
- **学習時間の目標と「遅れ」表示**：v1 にあったが、遅れの警告は罪悪感を生むだけだった。B 案では「予備が何週残っているか」だけ出す
- **制限時間付きの問題**：焦りは学習の邪魔になりやすい。タイムアタックは任意のおまけにとどめる

## 5. カリキュラムの骨格

### 量の見積もり

- 期間：2026-11-30（月）〜 2027-02-28（日）＝ **13週**
- 週3時間なら 39時間。年末年始などで2週くらい0時間になる前提で、**本線は約33時間（11週ぶん）**に収める
  - 新しい内容：約29時間
  - 復習（各セットの2問ぶん）：約4時間
- 週5時間なら1月中旬に本線が終わる → 残りは寄り道クエスト
- 1章あたり：問題 20〜30問（ブラウザ）＋ 工作1本（VS Code）

### 章立て

すべての工作物は、テキスト RPG「**コンソール・クエスト**」の部品として育っていく。

| 章  | 内容                                                | 目安      | 作る「動くもの」                                                                             |
| --- | --------------------------------------------------- | --------- | -------------------------------------------------------------------------------------------- |
| 0   | 起動：Hello、`java Xxx.java` で動かす、エラーを読む | 0.5h      | 自分の名前と HP を表示する「ステータス画面」                                                 |
| 1   | 変数・型・演算・文字列                              | 2.5h      | ダメージ計算機（攻撃力・防御力・会心の一撃）                                                 |
| 2   | 条件分岐・ループ・乱数・入力（`Scanner`）           | 3h        | **数当てゲーム**                                                                             |
| 3   | 配列・メソッド・`enum`                              | 3h        | **じゃんけんバトル**（勝敗を記録、5回勝負）                                                  |
| 4   | クラス・インスタンス・カプセル化                    | 3h        | `Monster` クラスで1対1のターン制バトル                                                       |
| 5   | 継承・インターフェース・ポリモーフィズム            | 3.5h      | 戦士・魔法使いなど職業違いのパーティバトル                                                   |
| 6   | コレクション（`List`・`Map`・`Set`）                | 3h        | アイテム袋と、手に入れたモンスターの図鑑                                                     |
| 7   | 例外・ファイル入出力・JUnit 入門                    | 3h        | セーブ／ロード機能＋そのテスト                                                               |
| 8   | ラムダ・Stream・`record`                            | 3h        | 戦績ランキング（集計・並べ替え・絞り込み）                                                   |
| 9   | Spring Boot 入門（REST API）                        | 4.5h      | ランキングを返す・登録する Web API（`GET /ranking`、`POST /scores`）。ブラウザで JSON を確認 |
|     | **合計**                                            | **約29h** |                                                                                              |

- 第9章は Spring Boot なので**全面的に VS Code**。ブラウザ側は「アノテーションの役割を当てる」「URL とメソッドを結ぶ」などの予測・並べ替え問題で支える
- データベース（SQL）と Git は、v1 のロードマップにはあったが今回の本線からは外し、寄り道クエストにする（お題の範囲が「基礎〜Spring Boot 入門」のため、週3時間で収める優先）
- 問題は「ブラウザで Java が動く前提」でも「動かない前提」でも同じ章立てで成立する（実行が必要なのは「書く」「改造」だけで、そこは VS Code にまわせる）

### 各章の中の流れ（例：第3章）

1. **見る**：完成したじゃんけんバトルが動く様子（実行 or 録画再生）
2. **予測**：「このコードは何を出す？」×5問
3. **並べ替え**：バラバラの行を正しい順に ×3問
4. **バグ探し**：「どの行がまちがい？」×3問
5. **穴埋め**：メソッドの1行を埋める ×5問
6. **書く**：小さなメソッドを1つ書く ×3問（ブラウザで実行 or 自己採点）
7. **工作**：VS Code でじゃんけんバトルを完成させる（判定コード付き）

## 6. 学習コンテンツの形式

### 問題の種類と所要時間

| 形式                       | 中身                                                               | 1問の目安 | ブラウザ実行が必要か                                                                         |
| -------------------------- | ------------------------------------------------------------------ | --------- | -------------------------------------------------------------------------------------------- |
| 出力予測                   | コードを読んで出力を4択 or 入力で当てる                            | 30〜60秒  | 不要（答えは作成時に JDK で実行して確定）                                                    |
| 並べ替え（パーソンズ問題） | バラバラの行を並べる。ダミーの行が1つ混ざる                        | 1〜2分    | 不要                                                                                         |
| バグ探し                   | まちがっている行をクリック                                         | 30〜60秒  | 不要                                                                                         |
| 穴埋め                     | 1か所を埋める。空白などを正規化して文字列で判定                    | 30〜90秒  | 不要（動けばテスト実行で判定）                                                               |
| 自分の言葉で説明           | 「このコードは何をしている？」を1行で → 模範解答と見比べて自己採点 | 1分       | 不要                                                                                         |
| 書く                       | メソッド1つを書く                                                  | 2〜5分    | 動けばブラウザでテスト。動かなければ模範解答と見比べて自己採点（「できた／あやしい／ダメ」） |
| 改造                       | 動くゲームのルールを1か所変える                                    | 3〜10分   | 動けばブラウザ。動かなければ VS Code                                                         |
| 工作                       | 章の成果物を作る（判定コード付き1ファイル）                        | 15〜60分  | VS Code ＋ 手元の JDK 25                                                                     |

- パーソンズ問題は、ゼロから書く問題と比べて短い時間で同程度の学習効果が出たという報告がある（Ericson らの研究。数値や条件の細部は**自信なし**）
- 出力予測とバグ探しは「読む力」を鍛える。仕事ではコードを書くより読む時間のほうが長い、という話はよく聞くが、根拠となる数値は**自信なし**

### 例1：出力予測（第1章・30秒）

```java
public class Main {
    public static void main(String[] args) {
        int hp = 10;
        int damage = 7 / 2;
        hp -= damage;
        System.out.println("HP: " + hp);
    }
}
```

- 問い：出力は？
  - A. `HP: 6.5`
  - B. `HP: 7` ← 正解
  - C. `HP: 6`
  - D. コンパイルエラー
- まちがえたときの解説（選択肢ごと）
  - A を選んだ → 「`int` 同士の割り算は小数点以下が切り捨て。`7 / 2` は `3`。小数にしたいなら `7 / 2.0`」
  - C を選んだ → 「`7 / 2` を 4 と考えた？ 四捨五入ではなく切り捨て」
- 技カード：「int の割り算」
- 間隔反復で数日後に出るときは、数字違い（`9 / 4` など）で出す

### 例2：並べ替え（第2章・1〜2分）

正しい順に並べる（字下げは自動）。**1行だけ使わない行が混ざっている。**

```
① System.out.println(count + "回目で正解！");
② for (int g : guesses) {
③ } else if (g > answer) {
④ count++;
⑤ System.out.println("もっと小さい");
⑥ if (g == answer) {
⑦ while (g != answer) {        ← ダミー
⑧ break;
⑨ } else {
⑩ System.out.println("もっと大きい");
⑪ }
⑫ }
```

完成形（出力：`もっと小さい` → `もっと大きい` → `3回目で正解！`）：

```java
public class Guess {
    public static void main(String[] args) {
        int answer = 42;
        int[] guesses = {50, 30, 42};
        int count = 0;
        for (int g : guesses) {
            count++;
            if (g == answer) {
                System.out.println(count + "回目で正解！");
                break;
            } else if (g > answer) {
                System.out.println("もっと小さい");
            } else {
                System.out.println("もっと大きい");
            }
        }
    }
}
```

- 入力は `Scanner` ではなく配列で固定している。ブラウザ内実行で標準入力が扱いにくい場合に備えるため（`Scanner` を使う本物の数当ては VS Code の工作で作る）
- 並べ終えたら（ブラウザ実行できる場合）その場で実行して出力を見せる。できない場合は記録済みの出力を再生

### 例3：書く → VS Code 工作（第3章・5〜15分）

アプリの「ファイルをコピー」ボタンで、次の1ファイルがクリップボードに入る。VS Code に貼って `Janken.java` で保存し、ターミナルで `java Janken.java`（JDK 11 以降は1ファイルならコンパイル不要で実行できる）。

```java
public class Janken {
    // 0=グー, 1=チョキ, 2=パー
    // 自分(me)が勝ちなら "WIN"、負けなら "LOSE"、あいこなら "DRAW" を返す
    static String judge(int me, int enemy) {
        // ここを書く
        return "";
    }

    // ===== ここから下は触らない（判定用） =====
    public static void main(String[] args) {
        int[][] cases = {{0, 1}, {1, 2}, {2, 0}, {1, 0}, {2, 1}, {0, 2}, {0, 0}, {1, 1}, {2, 2}};
        String[] expected = {"WIN", "WIN", "WIN", "LOSE", "LOSE", "LOSE", "DRAW", "DRAW", "DRAW"};
        int ok = 0;
        for (int i = 0; i < cases.length; i++) {
            String got = judge(cases[i][0], cases[i][1]);
            if (expected[i].equals(got)) {
                ok++;
            } else {
                System.out.println("NG: judge(" + cases[i][0] + ", " + cases[i][1] + ") -> " + got
                        + "（期待: " + expected[i] + "）");
            }
        }
        System.out.println(ok + " / " + cases.length + " 通過");
        if (ok == cases.length) {
            System.out.println("合言葉: " + Integer.toHexString(("janken:" + ok).hashCode()));
        }
    }
}
```

- 全部通ると `9 / 9 通過` と `合言葉: d0417cdc` が出る（2026-11-27 に手元の JDK 25.0.5 で確認済み）。アプリに貼るとクリア
- 途中までしか通らないときは、`NG:` の行がそのまま「質問文を作る」の【実行結果・エラー】欄に入る
- 模範解答の一例（クリア後に表示。if を並べた素直な解き方もあわせて出す）

  ```java
  static String judge(int me, int enemy) {
      int d = (me - enemy + 3) % 3;
      if (d == 0) return "DRAW";
      return d == 2 ? "WIN" : "LOSE";
  }
  ```

- 合言葉はズルできる（判定コードを消せば出せる）が、利用者は本人1人なので「自分との約束」として割り切る
- 参考：JDK 25 では `void main() { IO.println("Hello"); }` だけの1ファイルでも動く（手元で確認済み）。ただし研修や現場のコードに合わせ、問題は従来の `public static void main` の形で統一する。第0章で「新しい書き方もある」とだけ紹介する

### コンテンツの品質保証（ポートフォリオとしても見せられる部分）

- 問題データは JSON（または TS）で持ち、Zod で形を検証する
- **出力予測の正解は、CI で実際に JDK を動かして確かめる**（問題のコードを全部 `java` で実行し、登録してある正解と一致するかをテストする）。「アプリの正解がまちがっている」事故を防ぐ
- 工作の判定コードも、模範解答を入れた状態で CI で実行し、合言葉が出ることを確認する

## 7. 実装の難しさと MVP の範囲

### 難しさの見積もり

| 部分                                                         | 難しさ | メモ                                                                                                               |
| ------------------------------------------------------------ | ------ | ------------------------------------------------------------------------------------------------------------------ |
| セットエンジン・問題形式（予測・並べ替え・バグ探し・穴埋め） | 中     | 画面の部品が形式ごとに必要。ロジックは単純                                                                         |
| ライトナー方式の間隔反復・復習上限・難易度調整               | 低〜中 | 純粋関数で書けてテストしやすい（v1 の lib 層と同じ作り）                                                           |
| 技カード・XP                                                 | 低     | 判定は純粋関数                                                                                                     |
| 質問文ジェネレーター                                         | 低     | テンプレートに埋めてクリップボードへ                                                                               |
| VS Code 工作の判定コード＋合言葉                             | 低〜中 | 課題ごとに判定コードを書く手間がある                                                                               |
| v1 データの引き継ぎ                                          | 中     | Dexie のバージョンを上げて v1 の表を残したまま新しい表を足す。ログは読み取り専用で残す                             |
| CI で JDK を動かして問題を検証                               | 中     | GitHub Actions で `setup-java` を使う。無料枠で足りる見込み（公開リポジトリなら Actions は無料のはず。**要確認**） |
| ブラウザ内 Java 実行                                         | 高     | 別担当の調査しだい。MVP では外し、差し替え口だけ作る                                                               |
| **問題の作成（コンテンツ量）**                               | **高** | 本線だけで約200問＋工作9本。いちばん重い。後述                                                                     |

### MVP（最初に出すもの）

- 対象：**第0〜3章**（ゲームが2本動くところまで。約70問＋工作4本）
- 入れる機能
  - 即スタート画面、セットエンジン（5問）、「1問だけ」
  - 問題形式：出力予測／並べ替え／バグ探し／穴埋め／書く（自己採点）
  - ライトナー5段＋復習上限10問
  - 技カード（銅・銀・金）、XP、レベル
  - VS Code 工作（判定コード＋合言葉）
  - 質問文ジェネレーター、「分かったこと」カード
  - 実行意図の1タップ設定、おかえりモード、完走見込み
  - v1 データの引き継ぎ、エクスポート／インポート、PWA
- 入れない機能：ブラウザ内 Java 実行、難易度の自動調整（MVP は章の中の順番で固定）、統計、寄り道クエスト
- MVP の後の順番（案）
  1. 第4〜6章の問題を足す（12月中に第4章が必要になるので最優先）
  2. ブラウザ内 Java 実行（調査結果が出たら）
  3. 難易度の自動調整、過去の自分との比較
  4. 第7〜9章、統計、寄り道クエスト
- **コンテンツは「本人が解くより先に作る」必要がある**。週3時間ペースだと1章あたり約1週間で進むので、章の追加は常に1〜2章先行させる

### データ構成（ざっくり）

- 問題そのもの：静的ファイル（ビルドに含める）。IndexedDB には入れない
- IndexedDB（新しく足す表）
  - `attempts`：解答履歴（問題ID・日時・正誤・所要秒・形式）
  - `cards`：問題ごとの箱の段・次の期限
  - `skills`（技カード）：概念ごとのランク
  - `projects`：工作のクリア状況・合言葉・貼った出力
  - `notes`：「分かったこと」カード
  - `plans`：実行意図（きっかけ）
- v1 の `logs` などは残して読み取り専用の「旧記録」画面で見られるようにする

## 8. この案の弱点（正直に）

1. **問題を作る量が多い**
   - 本線で約200問＋工作9本。1問ごとに、まちがえた選択肢ごとの解説まで書くとかなりの量になる
   - 作成を Claude Code に手伝ってもらうのは現実的（アプリに AI 機能を入れるわけではない）が、正解の確認と解説の確認は人が必要。CI で正解を自動確認する仕組みで、負担と事故を減らす
   - 間に合わないと「解く問題がない」状態になり、それ自体が離脱の原因になる
2. **「ドリルっぽさ」が残る**
   - 5問セットは、ゲームデザインの案に比べると「勉強している感」が強い。工作物とRPGの物語でごまかしているが、ゲームとしての没入感は弱い
   - 「Java が面白くない」の根っこを、問題形式の工夫だけで変えきれるかは分からない
3. **スマホに流れる問題には、根本的には効かない**
   - 通知なし・PC 主体なので、アプリの外にいる自分を呼び戻す手段がない。「PC を開いたら」というきっかけ頼み
   - PC を開かない週は、どんな設計でもゼロになる
4. **間隔反復は、不定期な利用だと効果が落ちる**
   - 復習の期限が来ても開かれなければ出せない。上限10問で雪崩は防げるが、「最適なタイミングで復習」にはならない
   - 金カード（1ヶ月以上空けて正解）は、完走までの3ヶ月では数が少なくなりやすい
5. **ブラウザで Java が動かない場合、「書く」問題の判定が弱い**
   - 自己採点は甘くなりがち。結局 VS Code を開く必要があり、「1回が重い」の壁が工作の場面で戻ってくる
6. **合言葉はズルできる**
   - 本人だけが使うので問題にならない、と割り切っているが、判定の信頼性は低い
7. **カリキュラムの範囲を削っている**
   - SQL と Git を本線から外した。研修「Java上級」の中身が分からないので、外したものが必要になる可能性がある
   - 第9章の Spring Boot 入門は4.5時間しかなく、「動かして JSON を見た」程度で終わる
8. **研究の当てはめには限界がある**
   - 想起練習・間隔反復・実行意図・自己効力感は、それぞれ研究の裏付けがある手法だが、「この組み合わせで、この1人がやる気になる」ことまでは保証しない
   - 「85%ルール」「ツァイガルニク効果」「パーソンズ問題の効果の大きさ」は上に書いたとおり**自信なし**
