## 問題ごと

### ch01.variables（card）

- **指摘** 「値に名前を付けてしまっておく」が「付けてしまう」とも読める → 「値に名前を付けて、取っておく。」に直した。`concepts.yaml` の `variable` の1行も同じく直した
- 例の出力（`ユウ`／`30`／`ユウ HP 25`）は説明と一致

### ch01.status-line（fill）

- 問題なし。誤答（変数名を `" "` で囲む・`/` を忘れる・空白を忘れる）はどれもやりそう。ヒントが順に効く

### ch01.concat-order（predict）

- 問題文だけで答えが決まる。誤答は「数の足し算が先」「全部つなぐ」の思いこみで妥当
- **指摘** 解説の「1行目は」「2行目は」が、エディタの1・2行目（`void main() {`・`int hp = 3;`）にも読める（第0章で多かった誤り） → 「上の `println` は」「下の `println` は」に直した

### ch01.fix-type（fix）

- **指摘** ヒント3「型の宣言のほうは変えない」の「宣言」は未習（カードでは使っていない） → 「左の `int` は変えない」に直した
- 誤答 `StringType`（`String hp = "30";` にして引き算でエラー）は、とてもありそう

### ch01.arithmetic（card）

- **指摘** 計算の順番（`*` `/` `%` が `+` `-` より先）が書かれていない。次の modulo の `"1人 " + gold / 5` は、直前の concat-order の「左から順」だけでは読めない。damage の誤答 `NoParens` もこの順番で落ちる → 「`*` `/` `%` は、`+` `-` より先に計算する（算数と同じ）。`( )` があれば、その中が先。」を足した

### ch01.int-division（predict）

- 問題なし。誤答（`12.5`・四捨五入の `13`）はどちらもありそう。解説は出力と一致

### ch01.modulo（predict、おかわり）

- **指摘1** 誤答「のこり 4」は、どんな思いこみから出るのか説明できない → `%` を `/` と取り違えたときの「のこり 3」に替えた。正解がちょうど1つであることは content:verify で確認
- **指摘2** 解説に計算の順番が無い → 「`/` と `%` は `+` より先に計算するので、文字列とつなぐ前に数が決まる。」を足した（3行）

### ch01.level-up（fill）

- 問題なし。`=+` の誤答（エラーにならず 3 が入る）は気づきにくい間違いで、ヒント3と解説が対応している

### ch01.fix-uninit（fix）

- **指摘** ヒント3「宣言する行で入れる」の「宣言」は未習 → 「変数を作る行（`int damage`）で入れる」に直した
- 誤答（作った行の下でもう一度 `int damage = 4;`／使ったあとに入れる／`0` を入れる）はどれもやりそう

### ch01.damage（implement）

- 問題なし。ヒント1→2→3が「マイナスになる」→「大きいほうを使う」→「変数に入れてから連結」と段階的。3段目にコードは無い
- 3分は上限いっぱい。書くのは4行で、収まる

### ch01.string-methods（card）

- 問題なし。タイルの色（`=` が緑）は 05-visual-design.md 6-2 と一致

### ch01.hp-bar（draw）

- 問題なし。`full`・`empty` を計算済みにして、書くのは1行だけ

### ch01.bar-scale（fill、おかわり）

- 問題なし。ヒント3「かけ算を先にする」は方針だけで、式そのものではない。誤答 `DivideFirst`（空のバー）は解説と一致

### ch01.printf（card）

- 問題なし。例の出力（`のこり 7.0 割`）は `%.1f` の説明と一致

### ch01.status-frame（draw）

- **指摘** ヒント3「その数を足した式」の「その数」が 2 とも 4 とも読める。誤答 `PlusTwo`（片側の2だけ足す）にそのまま誘う → 「`# ` と ` #` は2文字ずつ。左右の両方のぶんを、`"#".repeat(…)` の `( )` の中で `line.length()` に足す。」に直した

## 直さなかったもの（指摘のみ）

- 判定が出力の比較だけなので、damage・status-line・hp-bar・status-frame は答えの文字列を直接書いても通る。問題文で「変数から計算する」と頼んでいる。テスト関数（`mode: tests`）が使えるフェーズ2で見直す候補
- `printf`・キャストは説明カードだけで、学習者が書く問題が無い。フェーズ2の `ch01.read-attack`（`printf` で出す）で書く。キャストは第1章では書かせないままになる
- 作品に飾る（`showcase`）のは status-frame だけで、枠の中に HP バーが無い。章の作品（ステータス表示と HP バー）に合わせるなら、枠の中にバーの行を足す案がある。中身が大きく変わるので作成担当の判断に回す
- 「残り」（hp-bar の本文）と「のこり」（modulo・printf の出力の文字）が混ざる。modulo の解説は出力の文字に合わせているので残した
