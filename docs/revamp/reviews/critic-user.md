## 0. 先に結論

- 一番「開きたい」と思ったのは **C**。最初の2分で自分のコードが絵になる。これは v1 になかった
- 一番「続けられそう」なのは **B** の入口。開いた瞬間に問題が出ていて、1問だけで終われる
- 一番「つまずきが楽しくなりそう」なのは **A** のエラー図鑑
- ただし3案とも、**「PC の前に座ってから、アプリを開くまで」** と **「アプリを作る時間が勉強を食う」** の2つに弱い。ここが v1 で失敗した場所そのもの
- 組み合わせるなら「C を土台に、B の入口と A のエラー図鑑を足す」。世界観は1つに絞る

## 2. 壁と好みへの効き方（5段階）

|                          | A 灯台守 | B ひとくち | C 工房 |
| ------------------------ | :------: | :--------: | :----: |
| 壁1 1回が重い            |    4     |   **5**    |   4    |
| 壁2 何から手をつけるか   |  **5**   |   **5**    | **5**  |
| 壁3 スマホや遊びに流れる |    2     |   **3**    |   2    |
| 壁4 Java が面白くない    |    4     |     2      | **5**  |
| 好み 動くものが作れる    |    4     |     3      | **5**  |
| 好み すぐ結果が出る      |    4     |     3      | **5**  |
| 好み ゲーム性            |    3     |     4      |   4    |
| 合計（35点）             |    26    |     25     | **30** |

### 理由

#### 壁1 1回が重い

- A（4）: 1灯5分、起動したらエディタ。途中保存で続きの1行から。ただ 5分の単位でも「書く」問題が中心で、ゼロ気力の日には少し重い
- B（5）: 開いた時点で問題文が読める。30秒で1問、「1問だけ」で終われる。入口の軽さは圧勝
- C（4）: 「▶ つづきから」1ボタンは良い。部品は5〜15分で、B より一段重い。zip の初回準備が重い

#### 壁2 何から手をつけるか

- 3案とも1本道で「次の1つ」しか出さない。差がつかない。ここは3案とも合格

#### 壁3 スマホや遊びに流れる

- 3案とも「スマホは止められない」と認めている。正直でいい。でも、ここで点は取れていない
- A（2）・C（2）: 予告や「すぐ結果」で、**開いた後**の引きを強くしているだけ。開く前には何もしない
- B（3）: 唯一「開く前」に手を打っている（実行意図、Dock、スタートページ・ログイン項目の案内）。ただし「案内」止まりで、機能の中心ではない

#### 壁4 Java が面白くない

- A（4）: `for` で灯台を描くのは楽しい。エラー図鑑で、つまずきにも意味がつく。後半の章は絵にならない
- B（2）: 4択と並べ替えが中心。工作物はあるが VS Code の中で、アプリの中の体験はドリル。「面白くない」の根っこには届かない
- C（5）: 全部品が絵・動き・表を出す。題材が1本のゲームで、書いたものがホームに反映される

#### 好み 動くものが作れる

- A（4）: 灯台・地図・マインスイーパー。港町の建物は配置が固定で、飾りに近い
- B（3）: 工作物は9本あるが、全部コンソール。しかも VS Code の中でしか動かない
- C（5）: 自分のダンジョンが v0.0 → v1.0 に育ち、最後は Web で遊べる。GitHub に置ける

#### 好み すぐ結果が出る

- A（4）: タイル描画とテストの灯りは良い。ただ「0.5秒以内に灯る」は言い過ぎ。調査では1回 0.45〜1.0秒、初回は 4.5MB のダウンロードがある
- B（3）: 正誤は1秒で出る。でもそれは「正解」であって「動いた」ではない。MVP にブラウザ実行がない
- C（5）: 実行 → キャンバスにアニメーション。間違えた選択肢でも「変な動き」が見られるのは良い

#### 好み ゲーム性

- A（3）: 図鑑と町で「収集」はある。でもポイント・レベルをあえて捨てている。私はレベルが上がるのが好きなので、ここは物足りない
- B（4）: XP・レベル・技カード。銅→銀→金が「時間を空けて正解」で上がるのは、収集と復習がつながっていて上手い
- C（4）: 工房レベル、部品図鑑、ギャラリー、ダンジョンのバージョンアップ。一番分かりやすく「育つ」

## 3. 一番強い仕掛けと、一番危ない点

|     | これがあるから開く                                                                     | これがあるから離脱する                                                                                                                                                                                                                                                 |
| --- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A   | **エラー図鑑**。直すのが一番つらい作業なのに、それが「捕獲」になる。ほかの案にない発想 | **絵にならない章の谷**（第1章、第5章以降）と**物語の寒さ**。さらに、図鑑の例（6-4 の NPE の詳しいメッセージ）は JDK のもので、ブラウザ実行（teavm-javac）では例外メッセージが null になる。図鑑はブラウザ内だと「例外の型」と javac のエラー（英語）でしか判定できない |

## 4. 最強の組み合わせ

### 方針

- **土台は C**（絵が出る・1本の作品が育つ）。私の「動くもの」「すぐ結果」に一番効くのはこれ
- **入口は B**（開いたら問題が出ている・1問だけで終われる・開く前の導線）
- **つまずきは A**（エラー図鑑・休んでも損しない）

### 採るもの

| 出どころ | 採るもの                                                              | 理由                                                                                 |
| -------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| C        | `Stage` で標準出力を絵にする仕組み                                    | teavm-javac でそのまま動く（標準出力さえ取れればいい）。手元ではターミナルに色で出る |
| C        | 1本の作品（ダンジョン）が章ごとにバージョンアップ                     | 「動くもの」と「続きが見たい」を同時に満たす                                         |
| C        | `void main()` から始めて、クラスの章で正式な形に移る                  | 最初の定型文が減る。調査で teavm-javac でも JDK 25 の書き方が通ると確認済み          |
| C        | 組み立てのチェックポイント、クリアコード、`java-quest` ワークスペース | 長い課題を15〜20分に切れる                                                           |
| C        | 遅れたら「近道ルート」に自動で切り替え                                | 2月末に間に合わせつつ、罪悪感を出さない                                              |
| C        | 質問カードに「今の学習段階」を自動で入れる                            | チャットの答えが未習の書き方に飛ばない                                               |
| B        | 起動時に「今日の1問目」がもう出ている                                 | クリック0回で始まる                                                                  |
| B        | 「1問だけ」ボタン                                                     | 1月の忙しい時期の命綱                                                                |
| B        | ウォームアップ＝復習1〜2問（ライトナー方式、上限あり）                | 3週空いても、易しい復習から戻れる                                                    |
| B        | 技カードの銅・銀・金（時間を空けて正解でランクアップ）                | 収集と復習がつながる。C の「部品図鑑」をこれに置き換える                             |
| B        | 質問文の「自分の予想を1行」、チャット後の「分かったこと」カード       | 質問する前に自分で気づける。分かったことが復習に回る                                 |
| B        | 開く前の導線（Dock、スタートページ、ログイン時に起動）                | 3案で唯一、壁3の「開く前」に効く。案内ではなく初回の設定手順に入れる                 |

| A        | 「修理」問題を各章に必ず入れる                                        | 図鑑の生き物に出会う場所                                                             |
| A        | 休むほど少し良くなる「おかえりの贈り物」                              | 休むことを損にしない。ダンジョンなら「宝箱」で置き換えられる                         |
| A        | 予言（出力予想）をウォームアップの形式に                              | 30秒で終わり、外れても学びになる                                                     |

| 捨てるもの                                 | 理由                                                                                                |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| A の灯台・港の世界観                       | C のダンジョンとぶつかる。世界観は1つにする（私はダンジョンの方が開きたくなる）                     |

### 組み合わせで出る矛盾と、どう決めるか

1. **1回の単位の大きさ**
   - B は30秒、C は5〜15分。両方は立たない
   - 決め方: C の部品を「ステップ」（1〜3分）に分けて、ステップごとに自動保存する。B の「1問だけ」は「1ステップだけ」にする
2. **復習と、1本の作品の進み**
   - 間隔反復は古い内容に戻す。作品は前に進む。混ぜると「今どこを作っているか」が分からなくなる
   - 決め方: 復習はウォームアップ枠（最大2問）だけ。本線の部品の中には混ぜない
3. **収集物が多すぎる**
   - エラー図鑑・技カード・部品図鑑・ギャラリー・港町・ダンジョンを全部入れると、どれも薄くなる
   - 決め方: 収集は「技カード」と「エラー図鑑」の2つ。作品はダンジョン1つ。ギャラリーはダンジョンの中の「記録」に吸収する
4. **`void main()` と `public static void main` の統一**
   - A・B は最初から `public static void main` で統一、C は途中で切り替える
   - 決め方: C の方式。研修で困らないように、切り替える章で「現場ではこの形」と明示する
5. **teavm-javac と手元の JDK の違い**
   - 組み合わせると、同じ問題をブラウザと VS Code の両方で解くことになる
   - `Scanner` がない、HashMap の順番・`Random` の値・例外メッセージが違う
   - C の第5章「迷路をランダムに生成」は、`Random` の値で判定してはいけない。A の第1章の `Scanner` はブラウザ側に代替クラスが要る
   - 決め方: 調査の提案どおり、CI で模範解答を JDK と teavm-javac の両方で実行して、出力の一致を確かめる
6. **機能を足すほど、開発が延びる**
   - 一番大きい矛盾。いいとこ取りをするほど、勉強を始める日が遅くなる
   - 決め方: 下の「5. 足りない視点」の1を参照

### 最小構成の案（組み合わせ版）

- 第0〜2章だけ（約5時間分）
- 入れる: つづきから＋起動時に問題表示、ブラウザ実行、`Stage` 描画、ステップ保存、「1ステップだけ」、ヒント3段、質問カード、エラー図鑑（10種ほど）、XP とレベル、v1 データの引き継ぎ、PWA
- あとで: 技カードの銀・金（1週間空けないと意味がないので急がない）、組み立てと zip（第1章の終わりまでに間に合えばいい）、近道ルート、贈り物

## 5. 3案すべてに足りない視点

### 5-1. アプリを作る時間が、勉強の時間を食う

- 今日は11月27日。2月末まで約13週しかない
- MVP の開発に2週間かかると、その2週間は Java を勉強していない。しかも開発は TypeScript
- v1 もそうだった。アプリは完成した。でも Java の勉強はしなかった（00-brief.md より）。作ることで「やった気」になった可能性がある（推測）
- 必要なこと
  - 「アプリ完成まで勉強しない」にしない。第0章だけの最小のページを数日で出して、そこから勉強を始める
  - 開発に使う時間と、勉強する時間を分けて決める（例: 開発は週1時間まで）

### 5-2. 効いているかを確かめる基準と、撤退ライン

- 3案とも「これなら続く」と言っているが、続いているかをどこで判断するかがない
- v1 は気づいたら使わなくなっていた。同じことを防ぐには、先に基準を決めておく
- 例: 「使い始めて2週間で、開いた日が4日未満なら、何が嫌だったかを書き出して直す」
- 確認するのはアプリではなく私。アプリの中に「2週間後の振り返り」を1回だけ出してもいい

### 5-3. 「PC を開いてから、アプリを開くまで」

- 3案とも「開いた後」の設計は細かい。でも私が負けるのは、PC を開いてブラウザを立ち上げた最初の10秒
- B が案内として書いている「ログイン時に起動」「スタートページにする」を、初回の設定手順に入れるべき
- macOS で、インストールした PWA をログイン時に開けるかは確認が必要（自信がない）

### 5-4. ネタバレ

- 教材を作るのは Claude Code と私。リポジトリに模範解答が入る
- A と C は触れているが「見ないと決める」しか対策がない
- 案: 教材は別ディレクトリにまとめ、私は「問題の形が正しいか」は見ず、CI の結果だけ確認する。それでも、ポートフォリオとしてコードを説明する場面では見ることになる。どこまで見ていいかを先に決めておきたい

### 5-5. ほかの勉強との取り合い

- 私には Java 以外にもやりたい勉強がある
- 3案とも、完走見込みは「Java だけをやる」前提で計算している
- 「今週は Java をやらない」と自分で決められるボタンがほしい。決めた週は見込みにも入れない。サボりではなく「選んだ」にする

### 5-6. 研修「Java上級」の中身を、アプリを作る前に確かめる

- 3案とも「中身が分からない」から逆算できていない。B は SQL を外し、C は DB をおかわりに回している
- 内定先か先輩に聞けば分かるかもしれない。分かれば「何から手をつけるか」が変わる
- これはアプリの機能ではなく、私がやること（聞くかどうかは私が決める）

### 5-7. 1月に何が忙しいか

- 3案とも「1月が忙しい」を一般論で扱っている。私の1月の予定（卒業制作・試験など）が分からないので、具体的にどのくらい減るかは分からない（自信がない）
- 分かっている予定なら、その週を最初から「休み」に入れておけるとよい

### 5-8. 使うブラウザ

- teavm-javac には WasmGC が必要（Safari は 18.2 以降）。初回は約4.5MB のダウンロードがある
- 私がふだん Chrome と Safari のどちらで開くかによって、初回体験と PWA の入れ方が変わる。3案とも前提を決めていない
